# Tinker contracts

The interfaces that beads share. SPEC.md says what the tool does; this file fixes names, shapes and file locations so that beads built separately in parallel worktrees fit together. If a bead needs to change something here, change this file in the same commit and say so in the PR body.

## 2. Graph format (`core/graph.ts`), version 2

The graph is an arbitrary DAG of operations. The user pins one or more outputs as predictions (ŷ) and exactly one as the loss (L). Training minimises L; `predict()` returns the ŷ ports. Roles are pins on output ports, never nodes. Model and objective regions are derived from the pins (ancestors of ŷ are the model; what L needs beyond that is the objective), never a fixed layout zone.

**Migration status.** Done (tinker-8xw.6): version 2 is the only graph. Everything in `@tinker/core` (parse, analyse, edit, layout, params, files), the engine and the web app takes and returns version 2, exported flat from the package root. Version 1 documents are still readable: `parseGraph` and `parseFile` read them with `core/v1.ts` and migrate them (below); nothing else knows version 1.

```ts
type NodeId = string; // [a-z][a-z0-9_]*, unique
type ActivationFn = 'sigmoid' | 'tanh' | 'relu' | 'gelu';
type LinkFn = 'sigmoid' | 'softmax';
type NormKind = 'l2' | 'l1';

type Node =
  | { id: NodeId; type: 'input'; columns: string[] }          // subset of the dataset's columns, in order
  | { id: NodeId; type: 'target' }                             // the dataset's y
  | { id: NodeId; type: 'feature'; degree: number; sin: boolean; cos: boolean; products: boolean } // degree 1..5
  | { id: NodeId; type: 'linear'; out: number; bias: boolean }  // out 1..64
  | { id: NodeId; type: 'activation'; fn: ActivationFn }
  | { id: NodeId; type: 'dropout'; p: number }                  // 0 <= p < 1
  | { id: NodeId; type: 'add' }                                 // a + b, same shape
  | { id: NodeId; type: 'link'; fn: LinkFn }                    // sigmoid or softmax, drawn as a link piece
  | { id: NodeId; type: 'subtract' }                            // a - b, same shape
  | { id: NodeId; type: 'square' } | { id: NodeId; type: 'abs' }
  | { id: NodeId; type: 'huber'; delta: number }                // elementwise Huber of a difference, delta > 0, default 1
  | { id: NodeId; type: 'log_loss' }                            // per example: -(y log p + (1-y) log(1-p)); pred is a probability (a Sigmoid link in front is fused; with none the pred is used as it is and must stay in (0, 1) while training)
  | { id: NodeId; type: 'cross_entropy' }                       // per example: -log p[class]; pred is probabilities (a Softmax link in front is fused; otherwise used as it is, rows need not sum to 1, entries must stay in (0, 1)), target a class index
  | { id: NodeId; type: 'mean' }                                // reduction over the batch (and elements): per-example -> single number
  | { id: NodeId; type: 'scale'; c: number }                    // c * x, any finite c
  | { id: NodeId; type: 'weights'; of: NodeId }                 // tap: reads W of the Linear `of` (not a bias)
  | { id: NodeId; type: 'norm'; kind: NormKind }                // sum w^2 (l2) or sum |w| (l1) of a weight matrix -> single number
  | { id: NodeId; type: 'column'; name: string }                // one dataset column by name, example(1); no input port
  | { id: NodeId; type: 'scalew' }                              // out = w * in, one learnable scalar (palette label "Weight")
  | { id: NodeId; type: 'bias' }                                // out = in + b, one learnable scalar; with no wire into `in` (optional port) out = b broadcast to [n, 1]
  | { id: NodeId; type: 'sum' }                                 // adds every wire into its one variadic port `in`
  | { id: NodeId; type: 'onehot' }                              // a category column (index) -> K 0/1 columns, no parameters (tinker-6t7.7)
  | { id: NodeId; type: 'lookup'; width: number };              // a category column -> row of a learned table W [K, width]; width 1..64, default 1 (width 1: one number per category; width > 1: an embedding)

type PortRef = string;          // "node" (its output) or "node.port"
type Edge = [from: PortRef, to: PortRef];

type Graph = {
  version: 2;
  nodes: Node[]; edges: Edge[];
  predictions: PortRef[];       // the ŷ pins, in order; may be empty
  loss: PortRef | null;         // the L pin
  data: DataConfig; train: TrainConfig;   // unchanged from version 1
  positions?: Record<NodeId, [x: number, y: number]>;   // where the user put pieces in the layer view (tinker-ong); absent when none
};
```

- Also exported: `DatasetName` and the `*_NAMES`/`*_FNS`/`LINK_FNS`/`NORM_KINDS`/`NODE_TYPES` const lists, `NodeBody`, `NodeOf`, `parsePort`, `resolveEdge(nodes, edge)`, `resolvePin(nodes, ref)` (a pin must name a node and, if it has a port, `out`), `inputPortsOf(type)`, `outputPortsOf(type)`, `variadicPortsOf(type)`, `isVariadicPort(type, port)`, `optionalPortsOf(type)`, `isOptionalPort(type, port)`. Types come from the zod schema.
- `parseGraph(json)`: version 2 as written, or version 1 migrated (below). Fills defaults (`standardize: false`, `huber.delta: 1`, `predictions: []`, `loss: null`). Rejects unknown fields and types, duplicate ids, a `weights.of` that is not a Linear, a pin that is not a node's `out`, and the same node pinned twice as ŷ. One plain sentence on failure. It does not check the pins' widths, that L is a single number or that L depends on a parameter: that is analyse (tinker-8xw.2).
- `serializeGraph(graph)`: always version 2, stable key order (`version, nodes, edges, predictions, loss, data, train`, then `positions` when any piece has one, in node order), two-space JSON. `loss: null` is written, not omitted.
- `positions` (tinker-ong): optional, one entry per piece the user moved: the top-left corner of the piece's box in layer-view layout units (section 9), so zoom and pan do not touch it. A piece with no entry sits where the automatic layout puts it. It is a graph field, so it is saved in files and presets, loaded with them and undone with the graph. It is a separate map, not a field on each node, so every node type (also those added later) can be placed with no schema change. `parseGraph` requires `[number, number]` pairs (finite) and drops entries whose id is not a node (so deleting a piece, or any edit that goes through `parseGraph`, cleans it); `positions` is never written empty. A position changes nothing the engine or analyse sees: `positions` is outside `structuralKey` in the train slice, so moving a piece does not recompile or stop a run. Neuron view ignores it. A Weight drawn as a wire (`collapsedWeights(graph)`, section 9) has no box, so it has no position: `moveNodes` refuses it and `serializeGraph` drops a stale entry for it. The far bound on a position is a cap, `positionLimits(nodeCount, limit?)` (section 8): `max(LAYOUT.pad + (nodes + 2) * pitch, limit)` per axis; `limit` is optional and given only by the web (tinker-31f).
- Ports. An input port may be optional (`bias.in`, tinker-7ab): left unwired it is not an issue. Every node has the one output port `out` (a port ref still allows more later). Input ports: `add` and `subtract` have `a` and `b`; `log_loss` and `cross_entropy` have `pred` and `target`; `input`, `target`, `column` and `weights` have none; `sum` has one variadic port `in`; every other piece (including `scalew` and `bias`) has one input port `in`. A bare node id means `out` as a source and the single input port as a destination.
- Every input port takes exactly one edge, except a variadic port (section 3, `variadicPorts`), which takes any number (at least one); an output port may feed any number of wires (fan-out, tinker-0sq; the only refused duplicate is the same source into the same port twice). Plan use counts in the engine count every reader of a node, wires and ŷ pin alike, so each reader but the last takes a `.ref` (tested: a node with three wires and a pin, 200 cycles, live-buffer count flat). The wires into a variadic port are ordered by their position in `graph.edges`. The same source cannot be wired into a variadic port twice. Sum is the only variadic piece.
- `weights.of` is a node field, not an edge: the tap reads a parameter, so it creates no data dependency and no cycle. The canvas draws it as a dashed wire from the Linear to the Weights node. Extension point for the scalar-level bead (tinker-9io): scalar weights on wires, a variadic Sum, a Bias and per-column inputs are new node types or a richer `of`; nothing here forbids them.
- ŷ and L are pins, so the same node can be both a ŷ and part of the loss path (the usual case: ŷ feeds the loss). A graph with no ŷ still trains when L is valid. Rules that analyse enforces: every ŷ width equals the dataset target (1 for regression and binary; numClasses for softmax classification); L is a single number that depends on at least one parameter.

### Version 1 migration

`parseGraph` migrates a version 1 document to a version 2 graph with identical math, widths and parameter counts (`core/migrate.ts`; tests run every engine fixture graph and bundled preset):

| Version 1 | Version 2 |
| --- | --- |
| Output(sigmoid or softmax) | `link` node, same id and fn; it is the ŷ pin |
| Output(identity) | removed; its source is wired to its consumers and the ŷ pin sits on that source |
| Loss(squared_error / absolute_error / huber(delta)) | `subtract(pred, target)` `{id}_diff` -> `square` / `abs` / `huber` `{id}_err` -> `mean` |
| Loss(log_loss / cross_entropy) | `log_loss` / `cross_entropy` `{id}_err` -> `mean` |
| the Loss's own id | the group's final node (the `mean`, or the penalty's `add`) and the L pin |
| penalty (kind, lambda) | for each Linear feeding the loss, in node order: `weights` `{id}_w_{lin}` -> `norm` `{id}_n_{lin}`; summed by `add` `{id}_sum{k}`; `scale(lambda)` `{id}_pen`; `add(a = mean, b = pen)`. The mean is then `{id}_mean`. A penalty with no Linear feeding the loss is dropped (it was 0) |
| everything else | unchanged, same id (so saved parameters keep their keys) |

The ŷ pin is the Output feeding the first loss's `pred`; with no loss, or a `pred` not fed by an Output, every Output is pinned. Only the first Loss gets the L pin. Generated ids are made unique against all existing ids (`_2`, `_3`, ...). Edges keep their order, with rewritten ends; the group's internal edges follow. Fusion (sigmoid then log loss, softmax then cross-entropy) is the engine's job; the diagram stays semantic, so `log_loss` takes the probability.

### Ready-made groups: macros, not group nodes

The five classic losses and the weight penalty are palette macros (`PaletteEntry.kind === 'macro'`): inserting one adds ordinary primitive nodes and edges (`lossSubgraph`, `weightPenaltySubgraph` in `core/macros.ts`, which migration also uses). There is no group node type, so analyse and the engine see only primitives. A macro returns `{ nodes, edges, inputs, out }`: `inputs` names the destination ports to wire into (`pred`, `target`; `total` for the penalty) and `out` is the node whose `out` is the result. The caller (web gestures, tinker-8xw.4) supplies a `Namer` that makes unused ids, wires the inputs, and sets the L pin.

## 3. Piece registry (`core/registry.ts`)

`PieceType` is the `type` of the nodes above (24 types). The palette (`PALETTE`) has one `piece` entry per type, with Sigmoid and Softmax as two entries of `link` and L2 and L1 as two entries of `norm`, (plus `column`, `sum`, `scalew` labelled Weight, `bias`, `onehot` labelled One-hot and `lookup` as single entries), plus six `macro` entries: `loss_squared_error`, `loss_absolute_error`, `loss_huber`, `loss_log_loss`, `loss_cross_entropy` and `weight_penalty`. The four activations are one type with `fn`.

```ts
// core/registry.ts
type Family = 'inputs' | 'features' | 'linear' | 'activations' | 'structure' | 'links'
  | 'errors' | 'losses' | 'reductions' | 'math' | 'parameters' | 'scalars' | 'categories';   // drop-to-swap only within a family
// inputs: input, target, column (column never swaps with input or target). scalars: scalew, bias. structure: dropout, add, sum (swaps need identical ports incl. variadic and optional flags, so bias and scalew do not swap, so sum swaps with nothing). links: link. errors: square, abs, huber.
// losses: log_loss, cross_entropy. reductions: mean. math: subtract, scale. parameters: weights, norm.

// What flows along a wire.
type Shape =
  | { kind: 'example'; width: number;           // one row of `width` numbers per training example
      category?: { column: string; count: number } } // only on a category column (below): width 1, the value is the category index
  | { kind: 'scalar' }                          // a single number
  | { kind: 'param'; rows: number; cols: number }; // a weight matrix, from a Weights tap
type ShapeError = { error: string };            // one plain sentence
type ShapeCtx = {
  dataColumns: number; numClasses: number;
  categories?: Record<string, number>;          // category count by column id, for the categorical dataset columns
  weightShape(linearId: NodeId): [rows: number, cols: number] | undefined; // [in, out] of that Linear's W
};
type CorePiece<N extends Node> = {
  family: Family;
  inputPorts: string[];                         // section 2
  variadicPorts?: readonly string[];            // subset of inputPorts that take many wires (default none). In outShape's inShapes such a port holds the one shape all its wires share; analyse checks that first
  defaults: () => Omit<N, 'id'>;
  outShape(node: N, inShapes: Record<string, Shape>, ctx: ShapeCtx): Shape | ShapeError; // missing key = port not connected
  categoryPorts?: readonly string[];            // input ports that take a category column (onehot.in, lookup.in); every other port refuses one
  paramShapes(node: N, inWidth: number, inShape?: Shape): ParamShapes; // `inShape` is the shape on the first input (a Lookup reads K from it). Named tensors, {} for a piece with none. Linear: { W: [in, out], b: [out] } (b only with bias). inWidth is 0 for a piece with no input port
  paramInit(node: N, inWidth: number, data: DataInfo): ParamInit; // data is the dataset info analyse was given (e.g. data.columns.length for a bound 1/sqrt(d)); existing pieces ignore it.
                                                                // how its tensors start; called only when paramShapes is non-empty. Linear: { kind: 'uniform', bound: 1/sqrt(in) }
  torch(node: N, inWidth?: number): string;
};
const CORE_PIECES: { [T in PieceType]: CorePiece<Extract<Node, { type: T }>> };

type PaletteEntry =
  | { kind: 'piece'; key: string; label: string; family: Family; make: () => NodeBody }
  | { kind: 'macro'; key: string; label: string; family: 'losses' | 'parameters';
      make: (name: Namer, opts?: { linears?: readonly NodeId[] }) => Subgraph };
const PALETTE: PaletteEntry[];

// engine/src/pieces/index.ts
const ENGINE_PIECES: { [T in PieceType]: EnginePiece<Extract<Node, { type: T }>> };   // tinker-8xw.3
// web/src/canvas/drawings/index.ts
const WEB_PIECES: { [T in PieceType]: WebPiece<Extract<Node, { type: T }>> };          // tinker-8xw.4
```

Shape rules (`outShape`):

- input: `example(columns)`, error with no column. target: `example(1)`.
- feature, linear, activation, dropout, link: need an `example` input (a scalar or weight matrix is an error sentence). feature `example(d·degree + (sin ? d : 0) + (cos ? d : 0) + (products ? d(d−1)/2 : 0))`; linear `example(out)`; the rest keep the width.
- add, subtract: both inputs must have the same shape (width for examples); the result has it. This is how the penalty total is formed from two single numbers.
- square, abs, huber, scale: elementwise, any shape passes through.
- log_loss: `pred` and `target` are `example`; pred width 1; result `example(1)`. cross_entropy: same, pred width any; result `example(1)`. Whether pred width matches numClasses and the target is analyse's job.
- mean: `example(w)` -> `scalar` (mean over the batch and the elements).
- column: `example(1)` (analyse issues when the name is not a dataset column). scalew, bias: need an `example` input, width passes through. sum: the shared shape of its wires (analyse has checked they agree).
- weights: `param(rows, cols)` from `ctx.weightShape(of)`; error when that Linear's input width is unknown. norm: `param` -> `scalar`.

Variadic ports (tinker-9io.2). A piece lists the ports that take many wires in `variadicPorts`; every other port keeps one wire. A variadic port with no wire is a dangling input (the piece's own "needs an input" sentence). Nothing but the registry flag marks a piece as variadic; core code asks `isVariadicPort(type, port)`. Optional ports (tinker-7ab): a piece lists ports that may stay unwired in `optionalPorts` (Bias lists `['in']`). An unwired optional port is not a dangling input and gets no entry in `outShape`'s `inShapes`; `outShape` then gives the piece's no-input shape (Bias: `example(1)`). Wired, the port behaves as before. Core code asks `isOptionalPort(type, port)`.

Categorical columns (tinker-6t7.7). A dataset column can be categorical (`DataInfo.columnKinds`, section 4); `x` holds the category's index (0..K-1) as a float. An Input of exactly that one column, or a Column naming it, has shape `example(1)` with `category: { column, count: K }` (an Input that mixes a category with other columns is an issue: "Input mixes the category column ... give the category its own Input."). A category column may go only to a port listed in `categoryPorts`: `onehot.in` gives `example(K)` (one 0/1 column per category, in the dataset's category order; no reference category is dropped, so with a Linear bias the columns are redundant, which gradient descent tolerates) and `lookup.in` gives `example(width)`; `lookup` owns `{ W: [K, width] }` (K rows, one per category), init uniform on +/-1 (torch `nn.Embedding` is N(0, 1); the HostParams values are what the fixtures compare). Every other consumer (Linear, Feature, Add, a ŷ pin, ...) fails with one sentence at that piece and wire: `"lin" needs numbers, but the category "x4" is a category; send it through One-hot or Lookup first.` Numbers into One-hot or Lookup is the opposite error ("One-hot needs a category column, but this input is 1 per example; switch on a category column in an Input."). Both directions are errors, not coercions. Invariant: the datasets only ever store integers 0..K-1; the engine still defines the other cases, rounding the float index, clamping it to [0, K-1] and mapping NaN to 0, so a stray value never gives an undefined one-hot (tested). `heldValues(dataset)` (core `data/grid.ts`) gives the raw value each column is held at in a 2-D slice (training mean; most common category for a categorical column); the fit plot and the resample overlay (`grid2dSlice` with `ResampleRequest.held`) both use it. `buildCsv` notes a single-value text column separately ("with only one value") from one with too many values. Palette family `categories` (swap between One-hot and Lookup keeps the wire; params re-init when the shape changes). Torch: `F.one_hot(x[:, 0].long(), K).float()`, `nn.Embedding(K, width)`.

Feature output layout (the order of columns; the engine and the torch fixtures use it): `x^p` for p = 1..degree (power-major, then column, so power 1 is x itself), then `sin(x)` if `sin`, then `cos(x)` if `cos`, then `x_i * x_j` for i < j in row-major pair order if `products`. sin and cos apply to the raw column values (no frequency scaling).

Scalar pieces: `scalew` owns `{ W: [1, 1] }` and `bias` owns `{ b: [1] }` (1 parameter each, any input width); both init `{ kind: 'uniform', bound: 1 / sqrt(d) }` with d = `data.columns.length` (the dataset's column count, so a scalar model starts at the scale of `nn.Linear(d, 1)`). Torch: `w * x`, `x + b` (Bias with nothing wired in: `b.expand(n, 1)`), `torch.stack(xs).sum(0)`, column `x[:, [i]]`. New ids from the palette: columns `x1`.., weights `w1`.. (smallest free), others `<type>k`. Engine (tinker-9io.4): `column` is a static slice `x[:, idx]` of the batch x (idx = the column's position in `DataInfo.columns`, `[n, 1]`; a static slice because index-array constants captured by a jit are never freed); `scalew` is `in.mul(W)` (W `[1, 1]` broadcasts), `bias` is `in.add(b)`, or with no `in` wire b broadcast to `[n, 1]` (`np.broadcastTo(b, [n, 1])`, n read statically off the batch x, which the step takes through `ctx.takeX()`; the walker counts such a Bias in `xLeft` and no array constant is created); the Bias parameter shape `{ b: [1] }` and init are the same wired or not, so `reconcileParams` keeps b when a wire is added or removed. A variadic port is wired as several entries in the compile-time port map, keyed `in`, `in#1`, `in#2`, ... in `graph.edges` order (the order of `analysis.inputs`); `sum` folds `.add` over its inputs in that order. `lossGrid` takes a Weight as `{ node, tensor: 'W', index: 0 }` and a Bias as `{ node, tensor: 'b', index: 0 }`.

Parameter count of a Linear: in·out + (bias ? out : 0). Every other piece has 0; the penalty's norms read Linear weights but own nothing. The penalty covers Linear weight matrices only, never biases.

## 4. Analysis (`core/analyse.ts`)

Analysis of a graph v2.

```ts
// DataInfo is defined in core/common.ts and re-exported by graph.ts.
type DataInfo = {
  columns: string[];                                  // column ids: always 'x1', 'x2', ... (what Input and Column pieces name)
  featureNames?: string[];                            // display names, same order as columns (real datasets); absent: show the ids
  kind: 'regression' | 'binary' | 'multiclass';
  numClasses: number;                                 // regression 1, binary 2, multiclass k >= 3
  targetName?: string;                                // 'y' for the synthetic sets
  classNames?: string[];                              // classification: numClasses names in label order
  columnKinds?: ('numeric' | 'categorical')[];        // per column; absent: all numeric. A categorical column holds the category index as a float; Standardise skips it (mean 0, std 1)
  categories?: Record<string, string[]>;              // category names by column id, for each categorical column (K = length); `categoryCount(info, col)` gives K or 0
};
type Pin = { role: 'loss' } | { role: 'prediction'; index: number };       // index into graph.predictions
type Issue = { at: { node?: NodeId; edge?: number; pin?: Pin }; message: string }; // edge = index into graph.edges
type Region = 'model' | 'objective';
type ParamShapes = { W?: [rows: number, cols: number]; b?: [number] };       // W is [in, out]
type Analysis = {
  order: NodeId[];                          // topological; what the roles need (below)
  shape: Record<NodeId, Shape>;             // output shape per node; absent where unknown
  inWidth: Record<NodeId, number>;          // example width entering the first input port, when known
  inputs: Record<NodeId, Record<string, { edge: number; from: NodeId }[]>>; // per node and input port: the resolved wires into it as graph.edges indices, in edge order. One entry for a plain port, all wires for a variadic port; the engine folds them in this order
  outWidth: Record<NodeId, number>;         // example width out; absent for scalar / param / unknown
  edgeShape: (Shape | null)[]; edgeWidth: (number | null)[];   // per graph.edges index
  params: Record<NodeId, number>;           // per node whose input width is known (0 for most)
  paramShapes: Record<NodeId, ParamShapes>; // per parameter-owning node whose input width is known (type ParamShapes = Record<string, number[]>)
  paramType: Record<NodeId, string>;        // piece type per node in paramShapes (reconcileParams re-inits when an id's type changed)
  paramInit: Record<NodeId, ParamInit>;     // same keys; ParamInit = { kind: 'uniform'; bound } | { kind: 'const'; value }, plain data
  paramNodes: NodeId[];                     // nodes with live parameters, in node order
  totalParams: number;                      // sum of params over paramNodes
  predictions: NodeId[];                    // nodes carrying the ŷ pins, in pin order
  lossNode: NodeId | null;                  // node carrying the L pin
  region: Record<NodeId, Region>;           // absent = neither
  modelOrder: NodeId[];                     // order restricted to the model region
  inert: NodeId[];                          // acyclic pieces no role needs while a pin resolves (see Inert pieces below); their own issues do not block
  paramWires: { linear: NodeId; weights: NodeId }[];   // weights.of wires, drawn dashed
  fusable: { link: NodeId; loss: NodeId }[];           // sigmoid -> log_loss, softmax -> cross_entropy
  issues: Issue[]; trainable: boolean;      // trainable = no issues
};
function analyse(graph: Graph, data: DataInfo): Analysis;
```

Trainable means no issues. Each failure is one Issue with one plain sentence, at the root cause only (a node whose upstream shape is unknown gets no issue of its own). `analyse` does not assume `parseGraph` ran: bad edges, unknown pins, a missing `weights.of`, duplicate ids and cycles all become issues.

Shapes come from the registry (`outShape`, section 3). Add and Subtract need equal shapes, no broadcasting; the mismatch is one issue at the node and the wire into `b`. On a variadic port every wire is an input (see `inputs`), they must all carry the same shape (otherwise one issue at the node and the first wire that differs from the port's first wire: "... needs every wire into its in input to carry the same kind of value ..."), and no doubly-fed issue arises (the same source wired in twice is one issue on the second wire, which is left out of `inputs`); a variadic port with no wire gives the piece's dangling-input issue. A doubly fed plain port uses the first wire; each later wire is an issue with its `edge` and the receiving `node`. A cycle is one issue at its first node; those nodes and anything downstream have no shape and are never in `order`. A port in `optionalPorts` with no wire is skipped by the dangling-input check (tinker-7ab); the piece then has no input shape, `inWidth` is 0 (as for a piece with no ports) so `paramShapes` and `totalParams` are still computed, and the inert and region rules are unchanged. Torch fixture `intercept_only_mse`: an unwired Bias pinned as ŷ, squared error, Mean as L.

Roles, each an issue when it fails:

- L: a pin must be set ("No loss is pinned ..." with `at: {}`) and name a node (`at.pin`). Its shape must be a single number (an example-shaped L says to add a Mean; a weight matrix is also refused), and its ancestors must include a parameter (a Linear, or a Weights tap of one). Pin issues carry `pin` and the pinned `node`.
- ŷ: several pins are allowed (the fit plot picks one, default the first); `modelOrder` is the union of their ancestors. A pin naming no node, or the same node pinned twice (one issue on the duplicate), is an issue. Each pin is checked on its own: it must be per-example with width 1, or `numClasses` when the pinned node is a softmax link; a softmax ŷ needs a classification dataset (`binary` or `multiclass`, not regression). A ŷ must not depend on a Target (issue on the pin). A graph with no ŷ pin still trains.
- Log loss and cross-entropy take probabilities: their `pred` may be any value of the right width. A `link` of the matching fn in front (sigmoid for log loss, softmax for cross-entropy) is listed in `fusable` and computed in the stable fused form; with no such link the pred is used as it is (tinker-ddg: students first optimise a probability directly, e.g. an unwired Bias pinned as ŷ), and there is no issue about the missing link. Log loss needs a `binary` dataset (on a `multiclass` one the sentence says to use cross-entropy with a softmax; on regression, "... needs a dataset with two classes, but this dataset is regression."), cross-entropy needs a classification dataset (`binary` softmax(2) or `multiclass` softmax(k)), and cross-entropy's pred width must be `numClasses`. 
- The 10,000 parameter limit applies to `totalParams` (issue with `at: {}`).

Regions and order. Ancestry follows data wires (the first wire into each plain port, every wire into a variadic port). Model = ancestors of the ŷ pins (including the pinned nodes). Objective = ancestors of L that are not in the model. `order` is the topological order of model plus objective when L or a ŷ resolves, so dangling nodes are left out; otherwise every acyclic node. **Inert pieces (tinker-l6y).** When at least one pin resolves, a piece that is neither in the model or objective region nor a Linear read by a live Weights tap (nor an ancestor of such a Linear, whose input width the tap needs) is inert: it is listed in `inert` (node order, acyclic nodes only; empty while no pin resolves), it is not in `order`, and the issues that come from working out its own shape or settings (a dangling input, a width or shape mismatch, an unknown column, a bad Weights `of`) do not block, so a piece dropped on the canvas and not yet wired never disables Train. Cycle and bad-wire issues still block wherever they are; the role checks (pins, L, ŷ, losses, parameter limit) only look at live pieces anyway. Wiring an inert piece into what a role needs makes it live and its issues apply from then on. Inert pieces have no live parameters (`paramNodes`, `totalParams` and the engine's tables skip them; an inert Linear's weights are not kept, and it is initialised afresh by `reconcileParams` when it becomes live), and the engine never compiles them. `modelOrder` is what `predict()` runs (dropout off). Wires from a Linear to a Weights tap (`weights.of`) are not data wires: the tap reads parameters, so it pulls in neither the Linear's inputs nor an ordering constraint, and a Linear read only through a tap is not in `order` (the engine does not run its forward pass). Such a Linear is still live: `paramNodes` lists every parameter-owning node in `order` (`ownsParams(node)`: its `paramShapes` is non-empty, so Linear, scalew and bias; exported from the registry) plus every Linear read by a Weights node in `order`, and `totalParams` and the engine's parameter tables use that list, not the keys of `params`. `paramWires` lists every Weights node whose `of` is a Linear, for the dashed wire.

`inWidth`/`outWidth`/`shape` have no key where unknown (never NaN or null). The records are prototype-free, so lookups by node id are safe for any id.

### Equations (`core/equation.ts`, tinker-96i)

`modelEquations(graph, analysis, data: DataInfo, host?: HostParams): { lines: EquationLine[]; numeric?: EquationLine[] }` with `EquationLine = { lhs; rhs; kind: 'pred' | 'loss' | 'def' }` (TeX without dollars; no DOM; never throws, a pin or piece that does not resolve just loses its line). Lines are the definitions (`h_k = ...`), the ŷ pins (`\hat{y}`, or `\hat{y}_{1}`, ... with several pins) and L, in that order. Walks `analysis.order`/`inputs`. A piece other than Input, Column, Target, Weights or an unwired Bias with more than one consumer in `order` gets a `def` line and is referenced as `h_k`; a ŷ node is `\hat{y}` wherever another line uses it. Under a Mean, per-example names carry the index (`\hat{y}_{i}`, `y_{i}`, `x_{i}`). Notation: Input `x` (`x_{[1,3]}` for a column subset), Column `x_{k}`, Linear `\mathbf{W}_{k}\,h + \mathbf{b}_{k}` (bold, so a Linear's parameters never collide with scalar pieces; k counts live Linears in node order; no `\mathbf{b}_k` without bias), Scalar Weight `w_{k}\,h` named by `weightTex(id)` (the same names as the pills; `weightTex` and `fmtWeight` live in core, `canvas/pure.ts` re-exports them), Bias `h + b_{k}` or just `b_{k}` unwired (plain, k counts Bias pieces) (plain, k counts Bias pieces), sum/add `a + b + ...`, subtract `a - b`, activations/links `\tanh`, `\mathrm{ReLU}`, `\mathrm{GELU}`, `\sigma`, `\mathrm{softmax}`, feature `\phi`, dropout `\mathrm{drop}_{p}`, scale `c \cdot (...)` (c as a number, always a dot), square `(...)^2`, abs, huber `H_{\delta}(...)`, log_loss `\mathrm{BCE}(p, y)`, cross_entropy `\mathrm{CE}(p, y)`, mean `\frac{1}{n}\sum_i (...)`, norm `\|\mathbf{W}_{k}\|_2^2` / `\|\mathbf{W}_{k}\|_1`, Weights tap `\mathbf{W}_{k}`. `numeric` (only with `host`, and only when every live parameter is a scalar piece or `totalParams <= NUMERIC_MAX_PARAMS` = 8) repeats the same lines with values (`fmtWeight`, signs folded: `x_{1} - 0.30`; a value that rounds to zero prints `0.00`, never `-0.00` (equations only; the pills keep `fmtWeight`); a value that rounds to zero prints `0.00`, never `-0.00` (equations only; the pills keep `fmtWeight`); a Linear's W is a number or a `bmatrix`; a norm is its value); it is absent when a value is missing. `wantsNumeric(graph, analysis)` is that condition and `numericExtras(eq)` the numeric lines that differ from the symbolic line with the same lhs (the strip shows only those); the strip computes step-0 weights only when it is open and `wantsNumeric`. `wantsNumeric(graph, analysis)` is that condition and `numericExtras(eq)` the numeric lines that differ from the symbolic line with the same lhs (the strip shows only those); the strip computes step-0 weights only when it is open and `wantsNumeric`.

## 5. Parameters, initialisation, randomness

```ts
// core/rng.ts
type Rng = { next(): number; normal(): number; int(n: number): number; fork(label: string): Rng };
function makeRng(seed: number): Rng;   // sfc32 or splitmix32; same seed -> same sequence on every platform

// core/params.ts
type HostParams = Record<NodeId, Record<string, Float32Array>>; // named tensors, row-major; Linear keeps W [in, out] and b [out]
function initParams(analysis: Analysis, seed: number): HostParams;
function reconcileParams(old: HostParams, oldAnalysis: Analysis, analysis: Analysis, seed: number): HostParams;
function countParams(host: HostParams): number;
function paramsToJson(host: HostParams): Record<NodeId, Record<string, number[]>>; // prototype-free object
function paramsFromJson(json: unknown, analysis: Analysis): { params: HostParams; dropped: NodeId[] };
function withStartParams(base: HostParams, start: HostParams | null, analysis: Analysis): HostParams; // tinker-6t7.9
```

Initialisation follows each piece's `paramInit` (plain data, carried in `analysis.paramInit`): Linear follows `nn.Linear`, W and b both uniform on ±1/√in; `{ kind: 'const', value }` fills a tensor. Different seeds give different values; the same seed always gives the same values. Note the layout: torch stores `weight` as [out, in]; HostParams stores [in, out] so that the forward pass is `x @ W + b`. Fixtures (section 11) are written in HostParams layout.

HostParams has an entry for every node in `analysis.paramNodes`, and may also hold frozen entries for inert owners (tinker-l6y): a parameter-owning node that still exists but no role needs keeps its arrays untouched (never compiled, trained or shown as live; `reconcileParams` keeps them while its `paramShapes` and piece type are unchanged and drops them when the node is deleted, its shapes change or its input width becomes unknown), so wiring it in again restores them bit for bit; the train slice merges them back when it reads the live state out of the engine. The engine's `fromHost` ignores entries it has no shapes for. Live entries are exactly the nodes in `analysis.paramNodes` (parameter owners on `order` plus Linears read only through a Weights tap) with a known input width; an entry has exactly the tensors of `analysis.paramShapes[id]` (for a Linear `b` iff it has bias). Each node draws its tensors, in the key order of its shapes (W then b), from `makeRng(seed).fork(nodeId)`, so adding a node does not change the others' init. `reconcileParams` takes the analysis the old params belong to (flat arrays alone cannot tell 2x3 from 3x2; `analysis.paramShapes` has the shapes, so no graph is passed). Per node: when every tensor present in both old and new shapes keeps its shape, those arrays (the same objects) are kept, a tensor only in the new shapes is drawn fresh from the node's rng stream and one only in the old is dropped (for a Linear: W is kept when [in, out] is unchanged even if bias was toggled; b is drawn fresh when bias is turned on and dropped when turned off); if any shared tensor changed shape, the node was not in the old analysis, or its piece type (`analysis.paramType`) changed (an id reused for another piece), the node is re-initialised; nodes that left the path are dropped; `old` is never mutated. `paramsFromJson` drops (never throws on) malformed entries (non-arrays, non-finite numbers, holes), entries whose tensor names or lengths do not match exactly (including an extra key, such as `b` on a Linear without bias) and unknown nodes, listing their ids in `dropped`; nodes with no saved entry are absent, so callers follow it with `reconcileParams`.

Group into Linear and Expand to scalars (section 8) carry host values between nodes with different ids: the Weight on column x_j becomes `W[j-1][0]` of a Linear (and back) and the Bias becomes `b`; the new nodes get exact copies, never a fresh init. A locked consumer of the replaced node may be rewired by these edits, since it receives identical values (section 8).

HostParams arrays are immutable once created: `reconcileParams` shares unchanged arrays with `old` (and so with undo history), so nobody writes into them in place. The engine's `fromHost` copies into jax arrays and `toHost` creates new arrays.

All data sampling, initialisation and mini-batch shuffling use `core/rng.ts`, never `Math.random` and never jax random. Only dropout masks use jax random, keyed from `TrainState.key`.

## 6. Data (`core/data/*`)


- Regression noise: y = f*(x) + noise · s · ε, ε ~ N(0, 1), where s is the standard deviation of f* over a uniform sample of the domain (a constant per set, computed once).
- Classification noise: Gaussian jitter of point positions with std noise · 0.5 (blobs: noise scales its std, 0.6 · (0.5 + noise)). Classes are balanced.
- n is the total; the last round(n · val) points are validation. Columns are named `x1`, `x2`.
- Categorical columns (tinker-6t7.7): `SetSpec.categories?: Record<columnIndex, string[]>` marks columns whose cells are category indices; `sample` puts `columnKinds` and `categories` (keyed `x1`...) in `info` and Standardise leaves those columns alone (`standardization.mean` 0, `std` 1, so `unstandardizeRows` and the grids stay identity there). `numericColumns(info)` lists the numeric column ids: a new Input starts with those (the data slice resets every Input to them when the set changes), never with a category. `categoryOf(analysis, info, nodeId)` (analyse.ts) gives the category column and names a node reads or carries, for the drawings and inspector. The fit plot holds a categorical column at its most common training category (lowest index on a tie), not at a mean, and cannot use one as an axis.
- Standardisation: when `config.standardize` is on, `xTrain` and `xVal` are stored already standardised, (x - mean) / std per column, with mean and population std (divide by n) of the raw training rows; a constant column gets std 1. `standardization` holds those numbers (null when off) and `domain` stays in raw units. `standardizeRows(x, d, st)` and `unstandardizeRows(x, d, st)` convert row-major arrays.
- `truth` takes raw (unstandardised) x. Regression returns f*(x). Classification returns P(y=1|x) of the clean generator: blobs the exact logistic of the two Gaussians, circle (cut at r = 1.15, mid-gap), xor and moons (class 1 = inner moon, the nearer half circle) 0 or 1. The v1 classification sets are binary (`info.kind` `'binary'`, `numClasses` 2); the multi-class sets have `info.kind` `'multiclass'` and `numClasses` k; regression has `numClasses` 1. `DataInfo` is defined in `core/graph.ts`.
- Classification labels cycle 0, 1, 0, 1, ... (binary) or 0, 1, 2, 0, ... (k classes) so the train and validation parts are each balanced to within one point. Multi-class labels are class indices stored as floats, like the binary ones.
- Dataset spec (`SetSpec` in `data/sets.ts`) fields for names, so a real dataset fills the same slots: `featureNames?` (default none; becomes `DataInfo.featureNames`, display only: `DataInfo.columns` stays `x1`, `x2`, ... so Input and Column pieces, the engine and scalar grouping never see feature names; changed in tinker-ei0, nothing used the earlier "featureNames become columns" wording), `targetName?` (default `'y'`), `classNames?` (default `'class 0'`, `'class 1'`, ...), and for multi-class `numClasses` (k >= 3). `sample` always puts `targetName` in `info`, and `classNames` for every classification set (binary included).
- `data/grid.ts`: `grid1d(domain, m = 200, standardization = null)` and `grid2d(domain, m = 64, standardization = null)` return `{ n, d, xRaw, xStd }` (row-major Float32Arrays; xStd equals xRaw when standardization is null). Both span the domain inclusive of the ends. grid2d row index is `iy * m + ix`, x1 varying fastest.
- Delivery story (tinker-6t7.4; `data/delivery.ts`, `docs/datasets.md`): a generated set for the running example, two set names over one generator. Columns `distance (km)`, `rain (mm/h)`, `queue (orders)` (`x1`..`x3`, plus the categorical `zone` as `x4`); target `late` (binary, classes `on time`, `late`) or `delivery time (min)`. Every column and outcome has its own `rng.fork` stream, so for a seed and n both sets have the same feature rows, and adding a column later changes no other. A fourth column, `zone` (`x4`, categorical: `centre`, `north`, `east`, `south` = indices 0..3, equally likely, own `rng.fork('zone')` stream, so the other columns' draws did not change), moves the outcome (late logit effects −0.6, −0.2, 0.2, 0.6; minutes −2, −1, 1, 2). d = 4, domain `[0, 3]` for zone. `truth` uses the row's own zone (x4); the fit plot slices zone at its most common category. `DELIVERY_LATE_RATE` stays the population rate (zones equally likely). `generate()` hands both delivery names to `generateDelivery`, which returns ordinary `Row`s (x with the zone index last). `n` and Resample (seed) work as for any generator. Noise: ignored by `delivery_late` (labels are Bernoulli, `SetSpec.noiseUnused: true`, the top bar hides Noise); for `delivery_time` the noise std is 10 · noise minutes (not `noise * spread`). Late labels are not balanced (true rate 0.341 (`DELIVERY_LATE_RATE`)); the cycling-labels rule above does not apply to this set. `delivery_lateness` (tinker-7bz) is a third name over the same generator: target `lateness`, classes `on time` (< 38 min), `late` (38 to < 49), `very late` (>= 49), cut from the same noisy time as `delivery_time` (same draws; about 50 / 35 / 15 percent at noise 0.3, not balanced, the cycling rule does not apply). Noise applies (it is the time's noise, 10 · noise minutes, so it sets the class overlap; at noise 0 the classes are deterministic); the top bar shows Noise. `SetSpec.probs(x, noise)` (optional, multiclass) gives exact class probabilities via the Normal CDF; `truthProbs` takes `noise` for it. Zone as a target is not offered.
- Real datasets (tinker-ei0; `data/real.ts`, `data/csv.ts`, rows in `data/real/*.json`). `SetSpec.real: true` marks a set with fixed rows: `iris` (multiclass, 150 x 4), `penguins` (multiclass, 342 x 4: bill length, bill depth, flipper length, body mass; rows with a missing value dropped, island, sex and year left out), `wine` (multiclass, 178 x 13), `diabetes` (regression, 442 x 10, raw units, target `progression`) and `csv`. The names, kind and classes of the bundled sets are static in `REAL_META` (also the sources and licences, shown by the Data menu's Sources dialog and in `docs/datasets.md`); `SETS.<name>` is built from them, so `analyse`, `scalar` and `edit` know `d` before the rows arrive. The rows are `{ x: number[][], y: number[] }` (y is the class index, or the target value) in a JSON file imported on demand: `loadRealSet(name)` (dynamic `import()`, so Vite makes a separate chunk served from the app's own origin; no third-party request at runtime) registers them; `hasTable`, `getTable`, `isRealSet`, `isBundled`, `hasTruth(set)` (false for real sets; `truth`, `truthMargin` and `truthProbs` throw for them) are exported. `sample` of a real set throws until its rows are registered, so callers `await loadRealSet` first (`dataSlice.chooseSet`, `loadParsed`, the store's data subscription do).
  - Split and size: n is the dataset size, `config.n` and `config.noise` are ignored (the top bar shows the size in a disabled n field and hides Noise). The rows are shuffled with `makeRng(seed).fork('split')` and the last `round(n * val)` are validation; Resample (seed) therefore re-splits. `domain` is the per-column min and max of all rows. Standardise works as for the generators. `numClasses` and `classNames` come from the set.
  - `csv` (`parseCsv`, `inferKind`, `usableInputs`, `buildCsv`, `registerCsv`, `CSV_LIMITS` = 5000 rows, 50 columns, 20 classes, at least 10 complete rows): a small parser (delimiter comma, semicolon or tab from the first line; quotes, `""`, quoted newlines, CRLF, BOM; the first row is the header; repeated or blank headers are renamed). A column is numeric when every non-missing cell is a number; missing is `''`, `NA`, `N/A`, `NaN`, `null`, `?`, `-`. `inferKind(target)`: 2 distinct values binary; numeric with 3 to 10 distinct integers multiclass; other numeric regression; text with 3 to 20 values multiclass; otherwise null (cannot be a target). The user may override the kind. `inputKind(csv, i)` is `'numeric'`, `'categorical'` (text with 2 to 20 distinct values) or null (one value, or text with more than 20 values: names, ids); `usableInputs` lists the columns with a non-null kind. `buildCsv(csv, { target, inputs, kind })` keeps a categorical text column as a categorical column: its categories are the sorted distinct values over every kept row of the whole file, collected before the train/validation split, so validation never holds a category that training lacks; the cell is stored as the category's index (`SetSpec.categories`). It drops the other text input columns (with a note) and the rows missing a value in a used column (with a note); classes are the sorted distinct target values; classification needs at least two numeric inputs (the 1-D fit plot is regression only). Every failure is one plain sentence (`{ ok: false, error }`). `registerCsv` replaces `SETS.csv` and its rows for the session only: a saved file records `set: 'csv'` but not the rows, so loading it in a session without the CSV is refused with a sentence (and the store falls back to `line` when a graph with a missing CSV is applied by undo). Nothing in core fetches: the web dialog (`topbar/CsvDialog.tsx`, `csvSource.ts`) fetches a URL only on the Fetch button (CORS permitting; errors: not an address, not http(s), unreachable or blocked, HTTP status, an HTML page instead of a CSV, over 2 MB) or reads a chosen local file.
  - `data/grid.ts` `grid2dSlice(domain, fixedRaw, ia, ib, m, st)`: the `grid2d` of columns `ia` (fastest) and `ib` with every other column at `fixedRaw` (length d); equal to `grid2d` for d = 2.
  - Web: `dataSlice` adds `chooseSet(name)` (async; loads a bundled set first, synchronous for generators), `csvName` and `openCsv(build, name)` (registers, switches to `csv`; when already on `csv` the seed changes so the new file is re-sampled). `setData` ignores a real set whose rows are not loaded. The Data popover has Open CSV and Sources buttons. The data subscription in `store.ts` loads the rows of a bundled set named by a loaded or undone graph and keeps the old dataset until they arrive.
- Web data slice (`state/dataSlice.ts`): the slice holds `dataset: Dataset` and `dataInfo: DataInfo` (`dataset.info`), always equal to `sample(graph.data)`; a store subscription re-samples whenever `graph.data` changes identity (data action, undo, redo, load). Actions: `setData(patch)` (clamps to the schema ranges; one undo step per call via `graphSlice.apply`, because history holds whole graphs including `graph.data`; the top bar commits number fields on blur or Enter, not per keystroke), `resample()` (new seed from `makeRng(seed).fork('resample').int(2 ** 31)`), `setInputColumns(id, columns)`. Switching to a set with different columns resets every Input piece to all columns of the new set.
- `data/batches.ts`: `batchSchedule(nTrain, batch, seed)` is an infinite generator of fresh `Int32Array` index arrays, one per step; each epoch shuffles with `makeRng(seed).fork('epoch' + e)` and cuts the order into batches, keeping a smaller last batch so every row appears once per epoch. `batch: 'full'` yields all rows in order every step. `stepsPerEpoch(nTrain, batch)` gives steps per epoch. `gatherBatch(xTrain, yTrain, d, idx)` copies those rows into a `Batch` (section 7).

## 7. Engine (`engine/src/index.ts`)

The SPEC interface, refined. All arrays crossing the interface are plain Float32Arrays; jax arrays never leave the package.

```ts
type Batch = { x: Float32Array; y: Float32Array; n: number };      // x row-major [n, d], already standardised if on
type Model = { readonly graph: Graph; readonly analysis: Analysis }; // graph version 2; plus private compiled closures
type Params = { readonly __brand: 'Params' };                        // opaque, owns jax arrays
type TrainState = { params: Params; opt: unknown; step: number; key: unknown };
type StepResult = { state: TrainState; loss: number; diverged: boolean }; // loss before the update; diverged if non-finite

interface Engine {
  compile(graph: Graph, data: DataInfo): Model;            // throws Error(first issue) when !analysis.trainable
  init(model: Model, seed: number): Params;                   // = fromHost(initParams(analysis, seed)); one entry per analysis.paramNodes
  fromHost(model: Model, host: HostParams): Params;
  toHost(params: Params): HostParams;                          // SPEC's read(); copies
  write(params: Params, nodeId: NodeId, values: Record<string, Float32Array>): Params; // named tensors of that node; consumes params
  startTraining(model: Model, params: Params, seed: number): TrainState; // consumes params; optimizer state from graph.train
  step(model: Model, state: TrainState, batch: Batch): StepResult;       // consumes state; dropout on
  predict(model: Model, params: Params, x: Float32Array, n: number): Float32Array[]; // dropout off; one [n, width] array per ŷ pin, in pin order; [] with no ŷ pin
  evaluate(model: Model, params: Params, batch: Batch): number;          // the L pin's value (a single number), dropout off
  exampleLosses(model: Model, params: Params, batch: Batch): Float32Array | null; // borrows all; jitted per model; the per-example values the Mean at the L pin averages (n values for log_loss / cross_entropy), dropout off, penalties excluded; null unless the L node is itself a Mean whose input is `[n, 1]` (a penalty added to the Mean, a pooling Mean inside the model or a wider input give null) (tinker-6t7.5)
  probabilityRange(model: Model, params: Params, batch: Batch): { node: NodeId; min: number; max: number }[]; // borrows all; non-jitted; per UNFUSED log_loss / cross_entropy of the loss plan: min and max of its pred
  lossGrid(model: Model, params: Params, batch: Batch, axes: [ParamAxis, ParamAxis], a: Float32Array, b: Float32Array): Float32Array; // [a.length, b.length]
  lossCurve(model: Model, params: Params, batch: Batch, axis: ParamAxis, values: Float32Array): Float32Array; // 1-D sweep of one parameter entry (tinker-6t7.2); borrows model, params; dropout off; one loss per value
  lossSlope(model: Model, params: Params, batch: Batch, axis: ParamAxis): number; // d(full-batch loss + penalty)/d(that entry) at the current params, dropout off, taken as a training step takes it (only leaves the loss plan reads are differentiated, like `makeStep`: a Weights-tap-only Linear gives W, never b; 0 for an unread leaf, so no constant buffer is left). Equals the step's gradient only for a full batch and no dropout; it is NOT the update direction for momentum or Adam
  trainMany(model: Model, seeds: number[], data: Batch[], steps: number): ManyResult[]; // vmap over k copies
  disposeModel(model: Model): void;                            // frees the jitted functions; idempotent
  clone(params: Params): Params;
  dispose(x: Params | TrainState): void;
  liveArrays(): number;                                        // for the leak test; method chosen by the spike
}
type ParamAxis = { node: NodeId; tensor: 'W' | 'b'; index: number };
type ManyResult = { params: HostParams; diverged: boolean };         // one trained copy of trainMany
function createEngine(): Promise<Engine>; // awaits jax init(); Wasm device; never WebGPU in v1
```

- "Consumes" means the caller must not use that value again; the engine disposes it or reuses its arrays. Everything else borrows. Callers that need to keep a Params (best-so-far, pins) take `clone` or `toHost`.
- The objective is the value at the L pin, a single number: whatever the graph computes (Mean of an error, plus a Scale of Norms of Weights taps, ...). `step` minimises it; `evaluate` reads it with dropout off; `predict` returns the ŷ pins' values with dropout off (a link is applied, so they are probabilities). The engine knows no loss names and no "penalty": a Weights tap reads the Linear's `W` (never `b`), so gradients from the objective reach `W` through the tap as well as through the forward pass. Shapes: per-example values are `[n, width]`; `target` is `[n, 1]` (a class index as a float for classification); Mean and Norm give a scalar; log_loss and cross_entropy give `[n, 1]`.
- Two plans are made at compile time. The predict plan is `analysis.modelOrder` (ancestors of the ŷ pins). The loss plan is `analysis.order` restricted to what the L pin reaches (a ŷ branch the loss does not use is not run, and its Linear is not read, in a loss pass). A Target in the predict plan reads zeros. The engine's `Layer` is `Record<string, jax Array>` (named tensors of one node) and `ParamTree` is `Record<NodeId, Layer>`; `takeLayer` and `layerUses` cover every `ownsParams` node plus Linears read by Weights taps (the tap keeps only `W` and releases the rest). Parameters come from `analysis.paramNodes` and `paramShapes`, not from `order`: a Linear read only through a Weights tap has parameters, is initialised and trained, and has no forward pass. A parameter a pass does not read is disposed by that pass; its gradient is zero.
- Stable fusion, in the loss plan only (the graph and the predict plan stay semantic): for each pair in `analysis.fusable` the loss node reads the link's INPUT, the logits, instead of the probability. log_loss then computes `logsumexp([z, 0]) − z·y` and cross_entropy `−logSoftmax(z)[class]`; both are finite for any finite logit (checked at ±5,000 in the loss, the prediction and the gradient). The link is still computed in the loss pass when something else uses its output. An UNFUSED log_loss or cross_entropy (its `pred` is not a matching link) does not clip: log_loss is `−(y log p + (1−y) log(1−p))` and cross_entropy `−log p[class]`, exactly as torch's `binary_cross_entropy` / `nll_loss` on probabilities; the rows of a cross-entropy pred are NOT required to sum to 1. A pred entry <= 0 or >= 1 is checked on EVERY step: for a model with unfused probability losses `step` uses a second jitted step (`stepRangeFn`, same body) whose forward pass also returns min and max of each such pred (reductions of values it already computes; no array constants), and `StepResult.ranges` carries them (`{node, min, max}` per loss, at the parameters the step started from; absent for models without unfused probability losses, whose step is unchanged). A range outside (0, 1) (NaN is divergence, not a range problem) makes the step `diverged: true` with the update NOT applied and the state unchanged, so the parameters stay where the prediction left the range; the log_loss is then non-finite anyway, the cross_entropy loss can be finite (`p[class] > 1`) or involve a non-picked entry. `trainMany` applies the same check per copy: for a model with unfused probability losses its vmapped step is built from `stepRangeFn`, and a copy whose pred range leaves (0, 1) at some step is frozen at its previous state and returned `diverged: true`, like a non-finite copy (no new flag; the others are bit-identical). For the paused checks (hand edit, compile, reset, load) the engine has `probabilityRange(model, params, batch)` (not jitted, borrows everything, frees everything): one `{ node, min, max }` per unfused log_loss / cross_entropy of the loss plan, the min and max over all entries of its `pred` on the batch (NaN when an entry is NaN). The web builds the sentence from `StepResult.ranges` when a step is refused, and from `probabilityRange` after a hand edit, compile, reset, restore and load; a range leaving (0, 1) shows "Log loss takes probabilities between 0 and 1, but the prediction reached 1.27." (`probIssue` in the train slice) instead of "diverged"; the run stops with its last finite parameters and a hand edit back into range clears it. There is no log-sigmoid primitive, so the "log(sigmoid)" form beyond log_loss has nothing to fuse yet.
- Huber follows `nn.HuberLoss(delta)`. Dropout follows `nn.Dropout` (inverted scaling 1/(1−p)).
- Optimizers: sgd = `optax.sgd(lr)`; momentum = `optax.sgd(lr, { momentum: 0.9 })` (equal to torch SGD with momentum 0.9, dampening 0); adam = `optax.adam(lr)` with b1 0.9, b2 0.999, eps 1e-8 (torch defaults). Adam is plain and can spike periodically near convergence (`tinker-df1`): on a noise-free sine fit (n=40, 1-8-8-1 tanh MLP, full batch, seed 1, lr 0.01 or 0.05) the loss, once near 1e-4, jumps every ~100-200 steps by up to 69x (lr 0.01) or 770x (lr 0.05) its running minimum and decays within a few steps. PyTorch 2.15 float32 `Adam` on the same data and init does the same (58x); SGD does not. Owner decision: do not damp it. Measured mitigations: larger eps (1e-7 to 1e-3), smaller b2 (0.99, 0.95) and 1/(1+t/k) lr decay (k 1000, 500) did not reliably remove it or removed it only by killing the lr (k 500); torch `amsgrad=True` still spiked early; a running max of the bias-corrected second moment removed it but was 3x-7x slower to reach small losses on presets. The UI carries no explanatory text. `mlp_tanh_adam_300steps` checks a long plain-Adam run against PyTorch.
- `step` never throws on divergence; it returns `diverged: true` and the state is unchanged.
- jax-js decisions (go/no-go `tinker-e1h.2`, from `docs/spike.md`; jax-js 0.1.27 and optax 0.1.3 stay pinned exactly):
  - Use `optax.adam` as is. It is accurate inside jit (matches torch Adam to about 1e-6 on the 5-step fixture); it is only inexact when run eagerly (float32 bias correction), which the engine never does. Switching optimizer means `compile` + `startTraining` again; `step` throws "This training state was started for a different optimizer; start training again." for a state from another optimizer, before consuming anything.
  - Sigmoid is computed as `0.5 * (1 + tanh(x / 2))` (jax-js `nn.sigmoid` has a NaN gradient below about −88), and the fused sigmoid + log_loss as `logsumexp([z, 0]) − z·y` (jax-js `softplus`/`logSigmoid` overflow in float32). These keep large logits from reporting a false "diverged".
  - ReLU, abs and GELU use the jax-js built-ins (`nn.relu`, `np.abs`, `nn.gelu` with its default tanh approximation). Their at-zero gradients (relu'(0) = 0.5, |x|'(0) = 1) differ from torch; accepted.
  - Laziness: jax-js evaluates lazily, so `step` and `trainMany` read the loss back every step. Without a read the pending computation grows with each step and the run slows and runs out of memory.
  - `step` keeps a `.ref` of the pre-step state until the loss is read, so a diverged step can return the state unchanged; the leak test includes a diverged step.
  - `liveArrays()` counts the Wasm backend's live buffers through the test-only hook in `docs/spike.md` (it finds jax-js's private slot map by intercepting `Map.prototype.set` until the first allocation). It is tied to the pinned version and is never used by the app: the hook lives in `engine/src/probe.ts` and is off unless a test calls `installProbe()` and then loads the engine with a dynamic `import()` (see `test/leak.test.ts`); without it `liveArrays()` returns 0. It does not count arrays of fewer than 128 elements with all values equal (jax-js keeps those as symbolic constants without a buffer; no memory, so harmless). The package exports it as `@tinker/engine/probe` so a dev build of the app can do the same.
  - Engine structure fixed by `tinker-hj4.1` (later engine beads fill files and flags, they do not change these):
    - `EnginePiece<N> = { forward(node, inputs: Record<port, JArray>, layer, ctx): JArray }` in `pieces/types.ts`; `forward` consumes its inputs and layer. `compile` walks the plan of each pass (above); an optimizer (`optim.ts` `OPTIMIZERS`) with `implemented: false` makes `compile` throw "The <name> optimizer is not implemented yet." `layer` is the node's own Linear's parameters, or for a Weights tap the parameters of the Linear it reads. `walk` hands out one reference per read (the Linear's forward pass and each tap) and `.ref`s a node's value for all but its last consumer.
    - `PieceCtx.fused(nodeId)` tells a log_loss / cross_entropy piece that its `pred` input is the logits (the compiler rewired the edge, see above).
    - Batch x is `[n, dataColumns]` (all dataset columns, `DataInfo.columns`); the Input piece selects its own `columns`.
    - A consumed `Params` or `TrainState` throws "already consumed or disposed" instead of touching freed arrays; `dispose` is idempotent. `step` consumes the state and its `params`: after a successful step the old `state.params` is dead; after a diverged step the returned state reuses the same `Params` object.
    - `diverged` is true when the loss is non-finite or any updated parameter is non-finite (a non-finite update is never kept); `loss` is then the value read, which may be finite. A batch that does not fit the model throws before anything is consumed.
    - `TrainState.key` is created from the seed; each `step` splits it (`np.unstack(random.split(key, 2))`), samples one keep mask per Dropout node on the loss path inside the jitted step but outside `valueAndGrad` (`PieceCtx.dropoutMask(nodeId)` hands it to the piece; random ops traced under `valueAndGrad` and `np.take` index arrays would become constants of the compiled function, which `disposeModel` frees with the jits) and stores the next key in the new state. Pieces must not create array constants (index arrays, `random.*`) inside the differentiated walk or any jitted function: jax-js never frees them (`tinker-daq`). Input uses one static slice per contiguous run of its columns, concatenated; the step differentiates only parameters the loss reads and builds zero gradients (`a.sub(a)`, not `zerosLike`) for the rest (prediction-only layers, the bias of a Weights-tap-only Linear). A diverged step returns the old key. `predict` and `evaluate` run with `PieceCtx.train = false` (Dropout is the identity).
    - Jitted functions (predict, evaluate, step, the vmapped `trainMany` step, the `lossGrid` functions) are built lazily per model and freed by `disposeModel(model)` (`tinker-klv`); a model that is dropped without it leaves its set until garbage collection. `@jax-js/jax` 0.1.27 is patched locally (`patches/`, `docs/spike.md` section 4b) because it leaked jaxprs through global caches; re-check the patch whenever the pin changes. `disposeModel` is idempotent; afterwards every method that takes the model throws "This model was disposed.". Params and TrainStates made for it stay valid arrays (`toHost`, `write`, `clone`, `dispose` work) but cannot be stepped or evaluated without a new model. The web app disposes the old model whenever it recompiles.
  - `trainMany` (`tinker-hj4.6`): copy i is `init(model, seeds[i])` + `startTraining(model, .., seeds[i])` + `steps` full-batch `step` calls on `data[i]`, vectorised: `jit(vmap(step))` over params, optimizer state (the scalar step count is broadcast to `[k]`), the dropout key (`random.key(seeds[i])`, so each copy has its own masks) and `x [k, n, d]`, `y [k, n]`. All `data[i]` must have the same `n` (it throws "All copies need training sets of the same size." otherwise); there is no padding or mini-batching. Everything is borrowed. The finite check reads one `[k]` flag every step (laziness). A copy whose loss or updated parameters become non-finite freezes at its last finite parameters, optimizer state and key and is returned with `diverged: true`; the other copies are unaffected (bit-identical to a run without it); when every copy has diverged the loop stops early. Arrays are passed to the jitted function as arguments, never captured; all arrays are disposed before returning (also on a throw). The vmapped step is cached per compiled model like the other jitted functions.
  - Ownership pitfalls found by the spike: optax `update` disposes its `params` argument; destructuring a jax Array leaks the parent (use `np.unstack` for split keys).

## 8. Edits (`core/edit.ts`)

Every canvas action is one pure function `(graph, args) -> EditResult`, with `type EditResult = { ok: true; graph: Graph; select?: NodeId } | { ok: false; error: string }`. The store applies `ok` results through the undo history and shows `error` as a toast; no edit mutates its input.

```ts
insertOnWire(g, edgeIndex, piece: NodeBody)               // new id = `${type}${k}`, smallest free k
insertMacro(g, key, at?: { edge: number }, pos?: [x, y])   // a palette macro (with `pos` and no `at`, its pieces are placed in columns by depth from `pos`, the top-left, positions clamped like moveNodes) (a loss or the weight penalty) as primitive nodes and edges; one edit. Last optional argument `limit?: [maxX, maxY]` (tinker-31f), as for `moveNodes`.
swapPiece(g, nodeId, piece: NodeBody)                     // same family only; carry over settings with the same name and valid value
connect(g, from: PortRef, to: PortRef)                    // replaces whatever fed `to` (a variadic port: appends); rejects cycles
deleteNode(g, nodeId)                                     // reconnects upstream to downstream when the node had one input and shapes still match; pins follow
deleteEdge(g, edgeIndex)
rewireEdge(g, edgeIndex, end: 'from'|'to', ref)           // move one end of a wire; one edit = one undo step; like `connect`, REPLACES any other wire already feeding the new port (onto a variadic port it appends; moving a wire off one removes only that wire; `end: 'from'` on a wire into a variadic port keeps its place in `edges`) (the UI dims that wire while dragging); rejects cycles; old and new destination must not be locked
setSetting(g, nodeId, key, value)                         // validated against the node schema
setLinearOut(g, nodeId, out)                              // neuron view +/-; 1..64
setColumns(g, inputNodeId, columns)
setLoss(g, ref | null)                                    // move the L pin to a node's output (or remove it with null); one undo step
addPrediction(g, ref)                                     // append a ŷ pin
movePrediction(g, index, ref)                             // move the ŷ pin at `index` (keeps its place in the order)
removePrediction(g, index)                                // drop the ŷ pin at `index`
addPiece(g, piece: NodeBody, at?: [x, y])                  // tinker-9io.6, widened in tinker-l6y: a new unconnected piece of ANY type (it is inert until wired, section 4); `at` is its top-left in layout units, clamped like moveNodes, else the automatic layout places it; selects it; one edit. A Weights tap reads the first Linear (refused when there is none). Fourth optional argument `limit?: [maxX, maxY]` (tinker-31f), as for `moveNodes`.
moveNodes(g, moves: Record<NodeId, [x, y]>)               // set `positions` for the pieces in `moves` (tinker-ong); one edit = one undo step; coordinates clamped to `LAYOUT.pad` or more and at most `LAYOUT.pad + (nodes + 2) * (boxW + layerGap)` in x and `LAYOUT.pad + (nodes + 2) * (boxH + rowGap)` in y (a far drag cannot grow the drawing without limit); refuses an unknown piece or a non-finite number. `moves` takes an optional third argument `limit?: [maxX, maxY]` (tinker-31f): a far-corner bound in layout units, the visible canvas's bottom-right minus one box; the cap on each axis is then the larger of the default and `limit`, so any spot the user can see is a valid place. The lower bound stays `LAYOUT.pad`. Without `limit` the result is unchanged (files, presets and tests stay deterministic). The web passes it from `visibleLimit(t, view)` (`canvas/dnd.ts`) for every move and drop.
clearPositions(g, ids?: NodeId[])                         // drop the saved positions of `ids` (default all) so the automatic layout takes over; refuses ("No piece has been moved by hand.") when none had one
// all edits except insertMacro, moveNodes and clearPositions refuse to change a node listed in `locked` (preset field, section 12): error "This piece is locked."
```

Choices fixed by the implementation (`core/edit.ts`, exports `EditResult` and `EditOptions`):

- Every edit (but `insertMacro`, which only adds) takes a last optional argument `opts?: { locked?: readonly NodeId[] }`; the store passes the preset's `locked`. A node counts as changed when its own settings change or a wire into it is added, removed or rewired (so `deleteNode` refuses when the piece or any piece it feeds is locked, and `insertOnWire`, `connect` and `deleteEdge` refuse when the wire's destination is locked). Source nodes are not changed by a new wire out of them.
- Every ok graph has been through `parseGraph` (defaults filled, huber `delta` 1), so it always re-parses. Edits never check trainability; `analyse` reports it.
- `insertOnWire`: the piece must have an input port (not Input, Target or Weights). The wire `a -> b` becomes `a -> new` at the same index and `new -> b` right after it; a two-input piece goes in on its first port. `select` is the new id. Pins: when the wire's source node is pinned (ŷ or L) and this wire is its only wire out, the pin moves to the inserted node (the pinned value now comes out of it); otherwise pins stay where they are.
- `insertMacro(g, key, at?)`: `key` is a `PALETTE` macro. Its ids are the suffix itself when free (`diff`, `err`, `loss`, `w_lin1`, `pen`, `total`), else `suffix_2`, `suffix_3`, ... With `at` (the wire it was dropped on) the wire's source feeds the group's first input and the wire stays; without it the group goes in free-standing. A loss group (`loss_*`) is fed its `pred` from that source or else the first ŷ pin, its `target` from the graph's Target (a new `target` node when there is none), and takes the L pin when none is set. `weight_penalty` reads every Linear, is fed the current loss (the wire's source, else the L pin) at `total.a`, and when that source carries the L pin the pin moves to `total`. A penalty with no Linear is refused. `select` is the group's result node. One edit, so one undo step.
- `swapPiece`: same family (`CORE_PIECES[type].family`) and the same input ports, so wiring always carries over (Dropout and Add, Weights and a norm, Subtract and Scale never swap) and the same variadic and optional flags (a variadic and a plain piece never swap; Bias, whose `in` is optional, no longer swaps with Weight); Input and Target never swap for each other; a macro never swaps. Wires move to the new piece's input ports by position; a swap that would drop a wire (e.g. a connected `subtract.b` when becoming a `scale`) is refused with one sentence, never silently. Same-type swaps carry over each setting that exists on the new type and still validates, except the identity key (`fn` of an activation or link, `kind` of a norm). The id is kept, so ŷ and L pins stay. `select` is the node.
- `connect`, `deleteEdge`, `insertOnWire`, `insertMacro` and `deleteNode` can shift edge indices, so the store and canvas must not hold edge indices across edits: re-derive them from the new graph (or use `select`).
- `connect`: stored in short form (`x`, `diff.a`); replaces every wire into a plain port (on a variadic port it replaces nothing and refuses a second wire from the same source), appended at the end of `edges`. Wires already leaving `from` are never touched: a connect from an output that has wires adds one more (fan-out). Refuses a bad port (resolveEdge's sentence), a self-wire or cycle, and an identical wire that already exists. It does not enforce shape or role rules (analyse does).
- `deleteNode`: closes the gap only when the piece has a single input port with exactly one wire in, at least one wire out or a pin, and the shape arriving equals the shape it passes on (a piece whose only input port is variadic closes when exactly one wire arrives, otherwise it does not; a closed wire that would duplicate one already into a variadic port is dropped) (or either is not yet known; shapes come from `analyse` on a data info built from the graph's Input columns). Each outgoing wire keeps its index and its source becomes the upstream node, and a ŷ or L pin on the piece moves to that upstream node (a second ŷ landing on a node already pinned is dropped). Otherwise the wires in and out are removed, the pieces downstream keep an open input and the piece's pins are dropped. Deleting a Linear also deletes the Weights pieces that read it (`weights.of` must name a Linear); locks on them count.
- `setSetting(g, id, key, value)`: `key` must be a setting of that piece type (`CORE_PIECES[type].defaults()` keys); `id` and `type` cannot be set; `undefined` removes the setting, which then takes its default. The value is checked by the node schema.
- `setColumns` refuses repeated columns but allows an empty list.
- Pin edits (tinker-8xw.4): `ref` is a node id (or `id.out`); `index` is into `graph.predictions`. Each changes only `predictions` / `loss` (nodes and edges are untouched) and is one edit, so one undo step. `setLoss` to the node that already has L is refused ("That is already the loss."); `addPrediction` and `movePrediction` refuse a node that is already a ŷ ("That piece is already a prediction."). *Locks:* a pin is part of the piece that carries it, so a pin edit is refused ("This piece is locked.") when the pin's old or new node is locked (`addPrediction` and `removePrediction`: the one node). There is no `removeLoss` in the UI (L is moved, never removed), but `setLoss(g, null)` exists for files and tests. *Macros and L:* a loss macro inserted when an L pin exists does **not** take it (the existing L stays; the new group is free-standing until the user drags L onto its result); it takes L only when none is set. That is the rule already in `insertMacro`, kept on purpose so inserting never silently changes what is trained.

- `moveNodes` / `clearPositions` (tinker-ong): change only `positions` (the result shares `nodes`, `edges`, pins, `data` and `train` with the input, which is how the train slice recognises a move). A locked piece **may** be moved: a lock protects what a piece computes (settings, wires, pins), not where it sits, and a preset author can lay out a lesson by hand.

Params after an edit: the train slice re-initialises the parameters of every node whose param shapes changed and keeps the others (`reconcileParams(oldHost, oldAnalysis, newAnalysis, seed)` in `core/params.ts`).

Scalar edits (tinker-9io.5, `core/scalar.ts`): these two change the graph and the host params together, so each is one pure function `(graph, host, ...) -> { ok: true; graph; host; select } | { ok: false; error }` and the store applies it as one undo step (the reconcile above then finds nothing to re-init, because every new node already has its values).

```ts
findLinearGroups(g, analysis): NodeId[][]            // one list per pattern: its Columns, Weights, Sum and Bias, in node order
groupIntoLinear(g, host, ids, opts?)                 // Columns -> Weights -> Sum (-> Bias)  =>  Input -> Linear(d, 1)
expandToScalars(g, host, linearId, opts?)            // Input -> Linear(out 1)  =>  Columns -> Weights -> Sum (-> Bias)
```

- Pattern: a Sum whose every input is a distinct Weight, each Weight fed by its own Column that names a dataset column (`x1..xd` of the set); Weights and Sum have no other wires; a Bias that is the Sum's only consumer (and takes only the Sum) is part of it. Only Columns feed a group (no other width-1 source yet). A group with an analysis issue on one of its pieces is not listed.
- `groupIntoLinear` always makes a fresh Input (`input<k>`, columns in dataset order) and Linear (`linear<k>`, bias iff a Bias was in the group); `W[k][0]` is the Weight of the k-th dataset column (so the wiring order does not matter), `b` the Bias; values are copied bit for bit. Consumers of the Bias (else the Sum) read the Linear, in place in `edges`; a ŷ or L pin on that node moves to the Linear. A Column with other wires out or a pin stays. Refused when `ids` is not exactly one pattern, a pin sits on a Weight (or on the Sum when a Bias follows), a removed piece is locked, or `host` lacks a value.
- `expandToScalars` makes `x<k>` Columns (the Input's columns, in order), `w<k>` Weights, `sum<k>` and `bias<k>` (smallest free ids), with Sum's inputs in that order; Weight k takes `W[k][0]`, the Bias takes `b`. The Input goes unless something else reads it or it carries a pin. Consumers and pins of the Linear move to the last node. Refused for out > 1, a feeder that is not an Input, an Input with no columns, a Weights tap on the Linear, a locked Linear or removed Input, or missing values.
- Locks: a locked consumer of the group's last node (or of the Linear) may be rewired by these edits, because it receives identical values; only the pieces that are removed or replaced must be unlocked. A graph that fails `parseGraph` after the edit is refused with one sentence, never the raw parser error.
- Round trip: group -> expand -> group returns the same params bit for bit and the same loss (engine test `scalarGroup.test.ts`).
- Web use (tinker-9io.7, `state/scalarActions.ts`): `groupSelected()` / `expandSelected()` call these edits with `host` = `currentHost()` (the exact parameters read from the engine at that moment, so a Running run loses no steps; `host` in the store can be a frame old) and apply `{graph, host}` as ONE undo step: `recordScalarEdit(prev, next, before, after, step)` (`state/weightHistory.ts`) keys both parameter sets and the step count by the new graph OBJECT, and `scalarHostFor(from, to)` returns the right side whenever the graph moves across the record (the edit, its undo, its redo); the train slice installs those params instead of reconciling. Callers must not clone the graph after `recordScalarEdit` (the lookup is by object identity). On the edit, step count, loss history and losses carry on (the function is unchanged); on undo or redo the weights are those of the edit, so step and history return to the recorded step and train and validation loss are re-evaluated on them. `best` is reset to the carried weights; the optimizer's own state (momentum, Adam moments) restarts. A run that is Running keeps running (values are identical, so loss continues); undo while Running discards training since the edit, the same rule as hand-set weights. After a divergence the edits are refused ("Reset first: the weights diverged."). `select` becomes the selection; a refusal is the toast.

## 9. Layout geometry (`core/layout.ts`)

```ts
type Box = { x: number; y: number; w: number; h: number };      // abstract units; the canvas scales to fit
type LayerLayout = { nodes: Record<NodeId, Box & { col: number }>; wires: { edge: number; points: [number, number][] }[]; size: [number, number] };
function layoutLayers(g: Graph, a: Analysis): LayerLayout;      // columns by longest path from inputs; a Target sits one column left of the first node it feeds, below the prediction; skip wires route above the main row
type NeuronLayout = { units: { node: NodeId; index: number; kind: 'in' | 'sum' | 'act' | 'out' | 'target'; x: number; y: number }[];
                      edges: { node: NodeId; i: number; j: number; from: [number, number]; to: [number, number] }[];  // one per weight W[i][j]
                      collapsed: NodeId[]; boxes: LayerLayout['nodes']; wires: LayerLayout['wires']; size: [number, number] };
function layoutNeurons(g: Graph, a: Analysis): NeuronLayout;    // a Linear expands only when in <= 8 and out <= 8; an activation directly after an expanded Linear is drawn as per-unit circles
```

Layout is deterministic. The automatic part stores nothing; the only stored input is the optional `graph.positions` (section 2).

Choices fixed by `layout.ts` (constants in the exported `LAYOUT`; all in abstract units):

- Both functions lay out the whole node set, not `analysis.order`. Duplicate ids: the first node wins. An edge that does not resolve (`resolveEdge` fails) gets no wire. Records are prototype-free.
- Columns: longest path; the edges out of a Target do not count (the Target is placed one column left of the first node it feeds), and a Weights tap counts as one column after its Linear (`weights.of` is not a wire); a cycle is broken at its first node in graph order; a node with no wires (other than Input and Target) goes in the last column. Rows: a node follows its first-listed source's row, moving down past taken rows; a Target sits one row below whatever else feeds the first node it feeds (the prediction).
- A wire's `points` run from the right-middle of the source box to the left side of the destination box, entering at height `(k+1)/(ports+1)` of the box for input port k (so `add.a` and `add.b` differ). The `m` wires into a variadic port (which then counts as one port) share that port's band, from half a slot above to half a slot below its centre, entering at its `j`-th of `m` evenly spaced heights, `j` ordered by the sources' vertical centres (ties by edge index); one wire enters at the centre as on any port. The formula is exported as `variadicSlotY(box, k, ports, slot = 0, count = 1)` (y of wire `slot` of `count` into port `k` of `ports`), for web hit-testing. Same in layer and neuron view. Adjacent columns: one elbow in the gap. Any other wire (skip, same column, backwards) rises into a lane above every box (shorter spans nearer the boxes), runs across, and drops in the gap left of the destination, so no segment enters a box interior. Each wire also has `labelAt: [x, y]`, the midpoint of its longest horizontal segment (first on ties); the web puts the width label there. Edges that do not resolve get no wire geometry (their issues must be shown at node or global level); doubly-fed edges and cycle edges do get wires.
- Manual positions (tinker-ong, layer view only; `layoutNeurons` ignores them). A node with `positions[id]` goes exactly there (x and y at least `LAYOUT.pad`; `col` stays the automatic column). A node with none stays where the columns put it, unless that overlaps a placed piece (or an automatic piece already pushed away, plus half a `rowGap`): it then moves down by whole rows (`h + rowGap`) until clear. Graph order, so the result is deterministic; two pieces both placed by hand may overlap, that is the user's choice. Wires between two untouched pieces keep the column routing above. A wire with a placed or pushed end is routed by `manualRoute`: forward (destination more than two `lane`s right of the source) a three-segment elbow whose vertical sits mid-way, or at the first of a few other x positions (quarter, three quarters, near either end) that crosses no other box; otherwise (backwards, or too close) a stub right of the source, a run above or below both pieces (the nearer side), a stub left of the destination. Not a full path search: if every try crosses a piece the mid-way elbow is used. Ends and `labelAt` follow the same rules as before (variadic slots still via `variadicSlotY`). `size` is then the extent of every box and wire point plus `LAYOUT.pad`; with no positions it is exactly the automatic size.
- Fan-out (tinker-0sq). Wires leaving one output port share the first run out of the port and the elbow (a tree), and each has its own row at the destination, so they never cross a box. A plain (non-weight) wire out of an output with several wires puts its width label on the last run instead of `labelAt`'s usual longest-run rule (which would tie on the shared run and stack every sibling's label): the middle of the last run (`[(gapR + x1) / 2, y1]`; `x1 - 14` in a gap widened by a weight pill, clear of the pill), or the middle of the last run of a `manualRoute`. Skip wires keep their lane label. Weight pills keep their `pillPitch` stagger. Two wires of one output into two ports of the same piece have labels about a third of a box apart; the hit-test label separation (`layerHitShapes`) already resolves such pairs.
- Weight wires (tinker-9io.6, layer view only). `collapsedWeights(g)` (in `graph.ts`) is the set of `scalew` nodes with exactly one resolved wire in, from a piece that is not itself a `scalew`, at least one wire out, and no ŷ or L pin (a pinned Weight keeps its box, so the pin has a port). In `layoutLayers` such a node is not laid out: it has no entry in `nodes` and takes no column (it is zero-width, so its source and its consumer are in adjacent columns), and each wire out of it becomes one wire from the Weight's source to the consumer, `from -> to`. That wire carries `weightNode: NodeId` (the Weight) and `viaEdge: number` (index of the wire into the Weight); its `edge` is the index of the wire out of it, so every existing use of `wires[].edge` (insert on a wire, rewire, selection by endpoints `{from: weight, to: consumer}`) addresses the half that ends at the consumer. A Weight with two consumers has one such wire per consumer (the same `weightNode`). A Weight that is fed by another Weight, has no wire in, or has no wire out keeps its box. The gap after a column that is the source of a weight wire is `layerGap + LAYOUT.weightGap` (64), so the pill fits; the pill sits at `labelAt`, which for a weight wire between adjacent columns is the elbow `[gapR, y0]` (mid-gap, source row), else the usual `labelAt`. Weight wires from the same source share that elbow, so their pills are staggered about the source row by `LAYOUT.pillPitch` (36) in edge order, and no two pills overlap (one source feeding several Weights, or one Weight with several consumers). Wires into a variadic port still take their slots (`variadicSlotY`), the Weight's source being the sort key. `layoutNeurons` does not collapse: a Weight is a box there, as in the graph. Hit-testing of the web uses `layout.nodes`, so a collapsed Weight is not a piece there.
- Neuron view uses a wider column gap. Unit circles per node: Input (`in`, one per column), expanded Linear (`sum`, one per output), an Activation whose first source is an expanded Linear (`act`, same count), Link (`out`, a sigmoid or softmax), Target (`target`, one); only when the width is known and at most 8. Everything else is a box. `boxes` covers every node (a unit column's box is the bounding box of its circles); `wires` connect boxes in both views.
- `edges[].from` is the unit centre of the upstream node when it has as many units as the Linear has inputs, else a point on the upstream box's right side spread evenly. `to` is the `sum` unit centre. Endpoints are centres; the web trims by the circle radius. Biases are not edges. `edges` is ordered by node (graph order), then i-major then j, so a node's edge index is `i*out + j`, matching HostParams `W` row-major `[in, out]`. `collapsed` lists every Linear that is not expanded, including ones with unknown widths.

## 11. PyTorch reference fixtures

`tools/torch-ref/gen.py` is a uv script with inline metadata (`# /// script` with `dependencies = ["torch==<current stable>", "numpy"]`), run as `uv run tools/torch-ref/gen.py`. It writes `packages/engine/test/fixtures/<name>.json`, one file per case, and is opt-in: tests never run Python.

```ts
type Fixture = {
  name: string;                       // e.g. "linear_bias", "loss_huber_delta0.5", "mlp_relu_adam_5steps"
  graph: Graph;                       // a complete trainable graph in the section 2 format
  params: Record<NodeId, { W: number[]; b?: number[] }>;   // HostParams layout [in, out], float64 written in full
  batch: { x: number[]; y: number[]; n: number };
  expect: {
    pred: number[];                   // predict()[0], post-link, [n, width] row-major (empty when the graph has no ŷ pin)
    predictions?: number[][];         // version 2 cases: every ŷ pin in order (`pred` is the first)
    loss: number;                     // evaluate()
    grads: Record<NodeId, { W: number[]; b?: number[] }>;  // d loss / d params
    after?: { steps: number; params: Record<NodeId, { W: number[]; b?: number[] }>; losses: number[] }; // optimizer cases
    dropoutMask?: number[][];         // dropout cases: the engine test injects this mask instead of sampling
    predEval?: number[];              // dropout cases: dropout-off forward (what predict() returns)
    lossEval?: number;                // dropout cases: dropout-off objective (what evaluate() returns)
  };
};
```

Details: in dropout cases `pred`, `loss` and `grads` are the dropout-ON training forward and backward with the given mask (how the engine test injects the mask is the engine's choice); `predEval` and `lossEval` are the dropout-off values that `predict` and `evaluate` must return. The fixtures record torch's at-zero conventions (L1 penalty subgradient sign(0) = 0 in `penalty_l1_zero_weight`, relu'(0) = 0 in `act_relu_zero_preact`), but the engine does not follow them: it uses `np.abs` (gradient 1 at 0) and jax-js `relu` (0.5 at 0), per the owner decision in tinker-e1h.2, so both fixtures are skipped (see "Engine exceptions"). `dropoutMask` is a 0/1 keep mask shaped [n][width of the dropout node]; the engine multiplies by mask/(1−p). The engine test injects it through the internal `debugTrainPass(model, params, batch, { [dropoutNodeId]: mask })` in `engine/src/compile.ts` (non-jitted dropout-ON forward, loss and gradients; not on `Engine`), and compares `predEval` / `lossEval` with `predict` / `evaluate`. Version 1 graphs in fixtures are read with `v2.parseGraph` (migrated), so every version 1 case also checks the migration; the `prim_*` cases are version 2 graphs (primitive losses, Weights taps and norms, a Linear read only by a tap, no ŷ pin, two ŷ pins, an auxiliary objective, a link that also feeds something else, a DAG with dropout, a skip and a feature piece, a 300-step Adam run; `prim_cross_entropy_softmax_k3`: softmax(3) with cross-entropy and Adam on class indices 0, 1, 2, written last in `gen.py` so adding it moved no other fixture's seed). Their torch reference evaluates the graph literally, primitive by primitive (a log loss on `sigmoid` probabilities), so it also checks the engine's fused forms. Classification targets in `batch.y` are class indices stored as floats (0 or 1; 0, 1 or 2 for the k = 3 case). `after.losses[k]` is the objective before update k+1 (so `losses[0] == loss`). GELU is the exact erf form (`nn.GELU()`); the engine uses jax-js `gelu` in its default tanh form instead (see "Engine exceptions" below).

Categorical cases (tinker-6t7.7): `categorical_onehot_linear` (a One-hot of x2, K = 3, into a Linear, added to a Linear of x1; Adam), `categorical_lookup_logloss` (Lookup width 1 of x1, K = 4, into Sigmoid and log loss; SGD) and `categorical_lookup_width3` (Lookup width 3, K = 4, into a Linear; momentum). `make_case_v2(..., cats={column index: K})` draws the category columns from a separate seeded stream (the other cases do not move); the fixture JSON gains a top-level `categories: { x2: 3 }` (column id to K) that `loadFixture` turns into `DataInfo.categories`. Lookup params are `{ W: [K, width] }` row-major. The engine's piece is `nn.oneHot` (jax-js, rounds the float index) times W; `PieceCtx.categoryCount(nodeId)` gives K from the analysis. `engine/test/categorical.test.ts`: a width-1 Lookup into Sigmoid and log loss converges to each delivery zone's sample late rate (within 0.01), One-hot into a Linear learns the zone effects, the live-buffer count stays flat over 1,500 steps and 100 compile cycles, and `trainMany` runs on a Lookup model.

Scalar cases (tinker-9io.4, version 2 graphs, scalar graph = Column -> Weight -> Sum -> optional Bias -> primitive squared error): `scalar_regression_d1`, `scalar_regression_d3`, `scalar_regression_d3_nobias`, `scalar_sum_two_cols` (one column enters the Sum unweighted), `scalar_activation_after_sum` (tanh after the Bias), `scalar_adam_5steps`. Params are keyed by node id: a Weight `{ W: [w] }`, a Bias `{ b: [b] }` (so `W` and `b` are each optional in `params`, `grads` and `after.params`), drawn uniform on +-1/sqrt(d). The graph's `data.set` is `plane` for d = 3 (no 3-column dataset exists); the engine tests take the dataset columns `x1..xd` from the batch width. `gen.py` asserts that `scalar_regression_d3` equals `nn.Linear(3, 1)` with `weight = [w1, w2, w3]` and `bias = b` (pred, loss, grads), and the engine test `scalar.test.ts` checks the same equality between the engine's scalar graph and `input -> linear(3, 1)`.

Gradients are not part of `Engine`, so the engine reference test reads them from one SGD step with learning rate 1 (grad = W before - W after).

Tolerance: 1e-5 absolute and relative on pred, loss and grads; 1e-4 on `after.params` after 5 steps. The case list is in the fixtures bead (`tinker-7x7.3`).

Engine exceptions (decided in `tinker-e1h.2`, because the engine uses jax-js built-ins and optax rather than torch-exact forms): `act_relu_zero_preact` and `penalty_l1_zero_weight` are skipped by the engine comparison test (they pin torch's at-zero subgradients); `act_gelu` is compared at 1e-4 (tanh-form GELU differs by about 3e-5). The fixtures stay as generated.

## 12. Files and presets (`core/file.ts`)

```ts
type SaveFile = { kind: 'tinker'; version: 2; graph: Graph; params?: Record<NodeId, { W: number[]; b?: number[] }> };
type Preset = SaveFile & { title: string; prompt?: string; instructions?: string[]; locked?: NodeId[] };
function parseFile(json: unknown): { ok: true; file: SaveFile | Preset } | { ok: false; error: string };
function parseFileText(text: string): ReturnType<typeof parseFile>;   // adds "This file is not valid JSON."
function serializeFile(graph: Graph, params?: Record<NodeId, { W: number[]; b?: number[] }>): string; // stable, 2-space, trailing newline
// TrainSlice: setRunSeed(seed): void; loadHost(host: HostParams): boolean  (false: engine ready but the model did not build)
```

`parseFile` opens file versions 1 and 2 (a version 1 file's graph is migrated; `params` keys are unchanged because Linear ids are kept, and a preset's `locked` ids are remapped through the migration's id map: a locked Loss covers its whole group, a spliced identity Output covers nothing) and `serializeFile` writes version 2. The web app has no other file reader: bundled presets (`web/src/presets/*.json`, native version 2 since tinker-8xw.5: Linear ids unchanged so seeded weights are identical, the squared-error group is `diff` (Subtract) -> `err` (Square) -> `loss` (Mean, the L pin), ŷ pinned on the last Linear, or on the `yhat` Link for sigmoid and softmax presets (the `softmax` preset: Linear(3) -> softmax `yhat` -> cross-entropy `err` -> Mean on `blobs3`); no preset has `locked` or `prompt`), Load and `?preset=` all go through `parseFile`.

A file with `title`, `prompt`, `instructions`, `locked` or `show` is a Preset. Save writes `tinker-model.tinker.json`; "Weights" saves the live parameters (`host`), not the best snapshot. Load sets the run seed to the file's `train.seed`, then replaces the graph as one undo step (`graphSlice.apply`); undo returns the previous graph with its weights reconciled as for any edit. The preset (title, prompt, locked; null for a plain file) travels with the graph in the undo history (`pastPresets`/`futurePresets` parallel to `past`/`future`; `apply(edit, preset?)` sets it with the graph): undo and redo restore the preset together with the graph, and `loadGraph` (a new graph) clears it. A locked list names ids of that graph only; ids it lacks are dropped on load. Loaded weights are installed with `loadHost` (new run: history and best cleared).

Saved params whose shapes do not match the graph are dropped with a notice, not an error. Bundled presets live in `web/src/presets/*.json` (`linear`, `logistic`, `sine`, `xor`, `skip`, `softmax`, `scalar`, `mlp`, `iris`, `intercept-prob`, `intercept-mean`; a preset that names a real set loads the set's rows first, see section 6); `?preset=<name>` loads a bundled preset on start, and a preset file can also be opened through Load.

Default start (tinker-9io.8): `initialGraph()` (web `state/graphSlice.ts`) is the bundled `scalar` preset (`presets/scalar.json`): Columns `x1`, `x2` -> Weights `w1`, `w2` (drawn as weight wires) -> `sum` -> `bias` (ŷ) -> squared-error group `diff`/`err`/`loss` (L) on the `plane` dataset. Its loss row is placed by hand with `positions` (a second row under the Sum and Bias) so the whole drawing fits at names >= 8 px on the narrowest s10 viewport (1024x768 touch); keep it that way when editing the preset. The former default is the bundled `mlp` preset (small ReLU network on `sine`). Saved params whose shapes do not match the graph are dropped with a notice, not an error. Bundled presets live in `web/src/presets/*.json`; `?preset=<name>` loads a bundled preset on start, and a preset file can also be opened through Load.

**Authoring `params` by hand.** `params` maps node id to its tensors: `{ "lin1": { "W": [...], "b": [...] } }` (W row-major [in, out]). A Weight (`scalew`) or a Bias (`bias`) also takes a plain number, which `parseFile` turns into the list form (`"w1": 0.5` is `{ "W": [0.5] }`, `"b": 0` is `{ "b": [0] }`); Save keeps writing the list form. `parseFile` fails with one sentence for a number on an unknown node, on a piece other than Weight or Bias, or a non-finite number. List-form entries that do not fit the graph are still dropped with a notice. Example (every learner starts at w1 = 0, w2 = 0, b = 0.5; Reset returns there):

```json
{
  "kind": "tinker", "version": 2, "title": "Start at zero",
  "graph": { "...": "as in presets/scalar.json" },
  "params": { "w1": 0, "w2": 0, "bias": 0.5 }
}
```

### Instructions panel (tinker-6t7.12)

A preset's optional `instructions` is a list of numbered steps, each a short string (TeX as in `prompt`, rendered with `TexText`). `parseFile` refuses a non-list, a non-string step and an empty step with a plain sentence; `[]` is accepted and shows nothing. `presets/InstructionsPanel.tsx` renders them as a collapsible panel at the top of the canvas region (full canvas width, steps list capped at `28vh` and scrolling inside), an `<ol>` with one `<li data-step>` per step (the slot a later success-check bead can add a tick to). The preset's `prompt`, when present, is the panel's title line and the prompt line is not shown (otherwise the title reads "Instructions"); the collapsed header is one line with the title and the step count. Collapse state is per-viewer component state, not saved, and resets to expanded when a different preset is loaded. Region id `instructions` (canvas group of `UI_IDS`, test ids `instructions`, `instructions-toggle`, `instructions-steps`). Save writes `instructions` back; a preset without it shows nothing new.

### Success checks (tinker-6t7.13)

```ts
type Check =
  | { kind: 'lossBelow'; value: number; split?: 'train' | 'val'; step?: number }          // split default 'train'
  | { kind: 'paramNear'; node: string; tensor?: 'W' | 'b'; index?: number; value: number; tol: number; step?: number };
// core/checks.ts: parseChecks(raw, graph, stepCount), evaluateCheck(check, {liveLoss, host}), evaluateChecks(checks, input)
```

A preset's optional `checks` is a list of conditions; `step` is a 0-based index into `instructions`. `lossBelow` holds while the live loss of the split (`liveLoss`, the objective L at the current parameters) is a finite number strictly below `value`. `paramNear` holds while `|host[node][tensor][index] - value| <= tol` (`tensor` defaults to the node's only tensor, `index` to 0; an ambiguous or missing tensor never holds). A `lossBelow` on `val` never holds when the validation fraction is 0 (the val loss is null). There is no `accuracyAbove`: no accuracy is computed in the store. Evaluation is pure and has no latch: a tick shows exactly while the condition holds, and goes when it stops holding. A step with several checks shows its tick when all hold; the checks without `step` share one tick (all hold).

`parseFile` refuses, with one plain sentence starting "The preset checks" or "Check N of the preset": a non-list, a non-object, an unknown kind, a missing or non-finite `value` or `tol` (`tol` is 0 or more), an unknown `node`, a `node` without parameters, a `tensor` the node does not have (or none given when it has both W and b), an `index` beyond the tensor's size (checked only when the shapes can be computed at parse time, otherwise at evaluation), a `tensor` other than W/b, a non-whole `index`, a `split` other than train/val, a `step` that is not a step of `instructions` (so none without instructions). Display: a step's tick sits in its `<li data-step>` (test id `success-check-step`); the shared tick (test id `success-check`) sits in the instructions panel header, or, when the preset has no instructions or its panel is hidden (`instructions` not in `show.ui`), in a thin row at the top of the canvas region (`presets/SuccessTick.tsx`). The tick is a check mark with the accessible label "Done" and no other text. `success-check` is a `canvas` id in `UI_IDS` and gates both forms. Save writes `checks` back.

### Start values and Reset (tinker-6t7.9)

The `params` of a loaded file or preset are the run's start values. The store keeps them as `startParams: HostParams | null` (`presetSlice`), set by the file loader after `apply` from what `paramsFromJson` accepted. Reset (and the fresh start after a divergence) draws a new seed, initialises every node from it, then `withStartParams` overlays the start values: a node with a start entry whose tensors fit its current shapes exactly gets those values, every other node keeps its seeded values. So `params` may be partial, and a file or preset without `params` behaves as before (random, Reset reseeds). Plain saved files with weights work the same way: Reset returns to what was loaded. Training does not change `startParams`; the Weights save still writes the live parameters.

When they are cleared or ignored: loading a file replaces them (a file without `params` clears them); `loadGraph` (a new graph) clears them; they travel with the graph in the undo history (`pastStarts`/`futureStarts`, parallel to `pastPresets`), so undoing a load restores the previous start values. A graph edit never edits them, but an entry applies only while its node exists with exactly the same tensor shapes (a Linear whose size changed is drawn from the seed on Reset; if the size is changed back, the start values apply again). Edits that keep the weights (`reconcileParams`) do not use them; only Reset does.

### Score readout modes (tinker-6t7.5)

`core/likelihood.ts`: `LossMode`, `lossModesFor(graph, analysis)`, `effectiveLossMode`, `exampleStats(losses)` (total, and the likelihood as a float32 running product of exp(-loss_i) with `Math.fround`, exactly 0 from 150 fair-coin rows). The train slice keeps `liveLoss` (L on the whole train and val sets, republished with `host`: once per frame while running and on every hand edit, so every readout mode follows a dragged parameter; the readout falls back to the history only while it is null), `lossMode` (the user's pick), `exampleStats` (likelihood, only while that mode is current) and `exampleLosses(split)`, the reusable per-example values of a split (`Engine.exampleLosses` on the whole train or validation set) that the per-example strip (tinker-6t7.6) uses. Mean shows L; total is n x L (when L is directly the Mean this is the sum of the per-example values, up to rounding; with a penalty or other terms it includes them); likelihood is offered only when L is directly a Mean over a log loss or cross-entropy, so likelihood = exp(-total) always holds. `exampleSource` returns the node feeding that Mean (null otherwise); `lossModesFor` gives total and mean when it is null.

### Progressive disclosure (`show`, tinker-6t7.1)

```ts
type Show = { palette?: string[]; ui?: string[] };   // Preset gains: show?: Show
const PALETTE_GROUP_IDS: readonly string[];            // core/file.ts, palette order (now with 'categories' after 'inputs', tinker-6t7.7); web Palette GROUPS uses the same ids
const UI_IDS: Record<'top-bar' | 'canvas' | 'results' | 'training-bar', readonly string[]>; // core/file.ts
const ALL_UI_IDS: readonly string[];                   // every id in UI_IDS
function isShown(list: readonly string[] | undefined, id: string): boolean; // absent list: true
```

A preset's `show` says what is visible; both lists are allow-lists, and an absent list (or no `show`) shows everything in its category exactly as before. `palette` takes palette entry keys (`PALETTE`, e.g. `sigmoid`, `loss_log_loss`) and group ids (a group id shows all its entries); `[]` removes the palette region. `ui` takes control and panel ids from `UI_IDS`, which are the controls' `data-testid` where one exists (`panel-fit`, `panel-loss`, `panel-surface`, `panel-histogram`, `panel-loss-1d` name the results panels). A region is on screen only while at least one of its ids is shown: with no `top-bar`, `results` or `training-bar` id listed that region is removed, and the others grow into its room (App grid, no gaps, no page scroll). `canvas` ids (`grain-toggle`, `fit-view`, `tidy-layout`, `reset-view`, `equation-strip`, `group-linear`, `expand-scalars`, `equivalence` (the scalar bar's two buttons and its equivalence line), `preset-prompt`, `instructions`, `success-check`) hide single canvas controls; the canvas itself is always there. `panel-controls` ids (`truth-toggle`, `resample-run` (the Resample button, its Clear and readout), `prediction-picker`, `loss-readout`, `loss-log-toggle`, `loss-restore-best`, `loss-1d-axis`, `loss-1d-explored`, `loss-1d-tangent`, `pins`) hide controls inside a results panel and never make the results region appear by themselves. The results region counts only panels that actually render: `panel-surface` alone on a model without a 2-parameter loss surface leaves no results region. The Data popover button shows only while one of its controls (`data-noise`, `data-val`, `data-seed`, `data-standardize`, `data-open-csv`, `data-sources`) is shown.

Hidden controls are not rendered (so not focusable) and their keyboard shortcuts are off (`btn-undo`/`btn-redo` for Ctrl/Cmd+Z, Shift+Z, Y). Hiding changes visibility only: a hidden optimizer still applies the preset's. `parseFile` rejects an unknown id, a non-list, or an unknown key in `show` with one sentence naming it. `show` makes a file a preset (it needs a `title`). The store keeps it as `show: Show | null` (`presetSlice`), `apply(edit, preset, show)` sets it with a file load, `loadGraph` clears it, and it travels with the preset in the undo history (`pastShows`/`futureShows`, parallel to `pastPresets`/`futurePresets`), so undoing a load restores the previous disclosure. Save writes it back with the other preset fields.

Later beads that add a panel, readout or control add its id to `UI_IDS` (and gate it with `useUiShown(id)` from `web/src/state/disclosure.ts`; `useRegionShown(region)` and `uiShown(id)` are the region and event-handler forms).

Step log (tinker-6t7.10): `panel-step-log` is opt-in like `panel-loss-1d` (shown only when `show.ui` lists it). The store keeps `stepLog: StepLogRow[]` (`trainSlice`): only Step adds a row (Run does not), models with at most 4 scalar parameter entries only, last 50 rows; cleared with the run (Reset, structural change, load, Restore best) and on a hand weight edit. A row holds the parameters and the first prediction (first training example, or the lone value with no input) AFTER the step, and the loss the step measured and the per-parameter slope (`engine.lossSlope`, full-batch, dropout off) from BEFORE it; the slopes are null (columns left out) unless the optimizer is plain `sgd`, the batch is full and the graph has no Dropout: otherwise the full-batch slope is not the step's gradient or the update is not lr x slope. `restoreBest` also clears the log.

Adding an id to `UI_IDS` changes nothing for a preset without `ui` (everything shows). A preset that has a `ui` list shows only what it lists, so a newly added panel or control starts hidden in such presets until the preset adds its id (confirmed: this is the allow-list behaviour; presets are widened deliberately).

### Label overrides (`labels`, tinker-6t7.11)

```ts
Preset.labels?: Record<string, string>;                // core/file.ts; ids from LABEL_IDS (a subset of UI_IDS)
const LABEL_IDS: readonly string[]; const LABEL_MAX_LENGTH = 40;
useUiLabel(id: string, fallback: string): string;      // web/state/disclosure.ts
```

A preset's `labels` renames controls and readouts: `{ "lr-slider": "Step size", "loss-readout": "Average surprise", "btn-run": "Keep stepping" }`. Labels are plain text (no TeX) everywhere, panel titles included. `parseFile` refuses, with one plain sentence each: a non-object, an id that is not in `UI_IDS`, an id that is in `UI_IDS` but not in `LABEL_IDS` (no text to change), a non-string, an empty or blank label, and a label over 40 characters. Ids not listed stay as they are. `LABEL_IDS`: every `training-bar` id; the `data-*` controls (`data-set`, `data-n`, `data-noise`, `data-val`, `data-seed`, `data-standardize`, `data-open-csv`, `data-sources`, `data-resample`); the canvas buttons `grain-toggle`, `fit-view`, `tidy-layout`, `reset-view`; the six `panel-*` ids (the panel title, and the splitter aria-label); `truth-toggle`, `loss-log-toggle`, `loss-restore-best`, `loss-mode-likelihood`, `loss-mode-total`, `loss-mode-mean`; and `loss-readout`, which has no title by default: an override adds a small title before the train and val values (and is the readout's aria-label). Details: `btn-run` renames Run only (Pause stays); the lr, speed, optimizer and batch selects show their values, so their label is the aria-label and tooltip (lr also shows it as its caption); `step-count` and `param-count` rename the caption before the number. Wherever a label is visible, the aria-label (and a tooltip where the text can be cut) follows it. Training bar: long labels are cut with an ellipsis (buttons at 150 px, captions at 130 px); the full text is in `aria-label` / `title`, so the bar never wraps or scrolls.

Labels travel with the preset: they live in `ActivePreset.labels` (so undo of a file load restores them, a plain file or new graph clears them) and Save writes them back. Components read a label with `useUiLabel(id, defaultText)`; a later bead that makes another control renamable adds its id to `LABEL_IDS` and uses the hook.

### Panel option defaults (`options`, tinker-59r)

```ts
Preset.options?: Record<string, boolean | string>;     // core/file.ts
const OPTION_BOOL_IDS: readonly string[];              // 'histogram-squares', 'loss-1d-tangent', 'loss-1d-explored', 'loss-log-toggle', 'truth-toggle'
useUiOption(id: string): [boolean, (v: boolean) => void];   // web/state/disclosure.ts
```

A preset's `options` sets the initial state of panel toggles, keyed by their `UI_IDS` ids: the five ids in `OPTION_BOOL_IDS` take `true`/`false`; `loss-mode` takes `"likelihood"`, `"total"` or `"mean"` (the readout mode). `parseFile` refuses, with one plain sentence each, a non-object, an unknown key, a non-boolean toggle and a bad `loss-mode`. The 1-D curve's axis is not an option. Semantics: the value is the toggle's state when the preset loads. If the control is shown the student can change it (the change is kept in the store, `optionEdits`, keyed to the preset object and `loadEpoch`, so a remount keeps it, while a new load, or undo/redo to a different preset, starts again from that preset's value); if `show.ui` hides it the preset's value stays fixed. Without `options` every toggle starts off, as before. `loss-mode` is applied once at load to the store's `lossMode` (a hidden mode still falls back as for `effectiveLossMode`); it is not restored by undo. `ActivePreset.options` carries the field and Save writes it back. Toggles that were component state (`FitPlot`, `FitPlot2D`, `LossCurves`, `TargetHistogram`, `LossCurve1D`) now read `useUiOption`.

## 13. Commands

From the repo root: `pnpm install`, `pnpm test`, `pnpm typecheck`, `pnpm lint`, `pnpm build`, `pnpm dev` (Vite on :5173), `pnpm e2e` (playwright-core against `pnpm preview`, added by `tinker-ysl.5`), `pnpm torch-ref` (runs the uv script; needs uv and network), `pnpm data-ref` (opt-in, Node and network: re-downloads the classic datasets and rewrites `packages/core/src/data/real/*.json`; the generated files are committed and tests never fetch). Per package: `pnpm --filter @tinker/<core|engine|web> <script>`.

- Names from the dataset (tinker-ei0; `state/names.ts`: `featureName(info, col)`, `fitText`, `inputLine`, `axisLabel`). The Input piece's secondary line lists the feature names of its columns (`sepal length, sepal width, +2`, cut with an ellipsis to the box); the Target piece shows `info.targetName` (nothing for the default `y`); a Column piece keeps its `x_{i}` glyph and shows its feature name as the secondary line; the inspector's Input checkboxes and Column select show feature names (the stored values stay `x1`..). Fit plot axes: 1-D uses the feature name and target name (`x` and `y` for the generators); 2-D uses the two feature names; the binary and multi-class keys use `classNames`. More than two inputs (`FitPlot2D`): two selects in the plot header (`slice-x`, `slice-y`, default the first two features, never the same) choose the axes; every other feature is held at its training mean (a slice through the model; all data points are drawn projected on the two axes). A real set has no truth, so the True function / boundary toggle is hidden, and the Resample overlay button is hidden (it redraws generated data). Layouts keep working at 1024 px: the header wraps.
- Math labels (tinker-mit, `web/src/tex/Tex.tsx`, `tex/tex.css`): all math is KaTeX, no Unicode stand-ins (`×` in plain UI text such as "Resample × 20" stays text). `Tex` (pure TeX), `TexText` (text with `$...$` parts; everything else is escaped React text), `SvgTex` (a `foreignObject` over a node-local box, `pointer-events: none`, used in `slotBox`, the badge circle, the tag and secondary lines of `NodeShell` and the neuron-view activation circle). `NodeShell`'s `glyph` and `tag` are now TeX (no dollar signs, e.g. `\hat{y}`, `\sigma(x)`); a `secondary` line containing `$` is typeset as mixed text. `renderToString` runs once per distinct source (cache), `trust: false`, `throwOnError: false`, `output: 'html'`; each `Tex` is `memo`ised and carries its TeX in `aria-label`. Fonts come from the `katex` package CSS through Vite (no network). Canvas-2D plots draw no axis titles: `plot/AxisLabels.tsx` is an HTML overlay in the plot's `position: relative` box (`drawAxes` lost its two label parameters); `axisLabels` returns `$...$` text. Preset prompts, pin labels (`pinLabel` returns `$...$` text; use `plainOf` for titles and aria-labels), the Inspector parameter count and the resample readout use `TexText`. Dev counters: `window.__tinker.tex` = `{ renders, katexCalls }`.
